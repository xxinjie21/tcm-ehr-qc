## 三、thresholds 结构 / 判定优先级 / 分数→三档映射

### 3.1 新 `Thresholds` 结构（`QcRuleSet.java:118-134`）

```java
@Data
public static class Thresholds {
    /** 合格（复核上限）：得分 ≥ reviewUpper 判合格 */
    private int reviewUpper = 80;
    /** 无效线：得分 < invalid 判无效 */
    private int invalid = 60;
    // 删除 seriousFullMissing
}
```

### 3.2 判定优先级（`QcScorer.java:112-123`，从上至下命中即定级）

```
1. score < thresholds.invalid          → 无效
2. 存在逻辑冲突 (conflicts 非空)        → 待复核
3. score < thresholds.reviewUpper      → 待复核
4. score >= thresholds.reviewUpper     → 合格
```

- 变更点：删除 `boolean serious = fullMissing >= th.getSeriousFullMissing()`；`getQualified()` → `getReviewUpper()`。
- `fullMissing` 变量仅剩扣分用途（不再参与判级）。
- 分数原值继续写 `records.score` / `qc_results`；`StatsCache.GRADES` 保持三值不变。

### 3.3 分数 → 三档映射（**唯一落地口径 = 3.2 的分数判定**）

| 总分区间 | 分级 | 备注 |
|----------|------|------|
| ≥ 80 且无冲突 | 合格 | — |
| 60–79，或有逻辑冲突 | 待复核 | 冲突永远拉回待复核 |
| < 60 | 无效 | 只看分数 |

### 3.4 与实测台阶对照（*仅用于论证阈值合理性，不落地*）

`weightFull=12` 下，**仅完整性扣分时** 分数 = `100 − 12×缺失数`：

| 核心要素真缺失数 | 得分 | 3.3 结果 |
|------------------|------|----------|
| 0 | 100 | 合格 |
| 1 | 88 | 合格 |
| 2 | 76 | 待复核 |
| 3 | 64 | 待复核 |
| ≥4 | ≤52 | 无效 |

> ⚠️ 真实病历会叠加格式/一致性/标准化扣分，分数会跨出台阶 —— 所以**判定只看分数（3.2），本表只解释 80/60 为何合理**。

### 3.5 预期分布（35354 份，据 `质控标准与报告口径改造计划.md` §3.10 的 fm × 分数档表）

| 分级 | 占比 | 数量(约) | 对比原口径(95/60/3) |
|------|------|----------|---------------------|
| 合格 | 84.6% | 29,905 | 60.7% |
| 待复核 | 4.7% | 1,662 | 27.0% |
| 无效 | 10.7% | 3,787 | 12.3% |

> **实测（2026-10-15 存量重算，35324 份）**：合格 **27931（79.1%）** / 待复核 **3711（10.5%）** / 无效 **3682（10.4%）**。
> 与上表差在「待复核偏高」（10.5% vs 4.7%）—— 上表按 §3.10 的**完整性单维台阶**估算，而真实病历会叠加格式/一致性/标准化/重复扣分，把一批本在 80–88 的病历压到 60–79；方向与量级均符合预期（合格 +、待复核 −、无效 −），属口径叠加而非 bug。

## 四、风险边界说明（误报 / 漏判）

**易误报（好病历被判重）**
- 漏抽误判：NLP 未抽取但原始列有 → 记"漏抽"扣 `weightPartial`；抽取率低时批量扣分。→ `weightPartial(6)` 显著低于 `weightFull(12)` 已缓解。
- 标准化误伤：词典未收录的正确术语被记未命中；舌/脉/治法已豁免。
- 一致性 `contains` 误配：如证候否定/并列语境被误触发（本次不改 `LogicChecker`，登记为后续版本风险）。
- 合格率偏高：`reviewUpper=80` 预计合格率 84.6%（原 60.7%），须确认符合三甲评审对"合格率"的期望。

**易漏判（高危未拦截）**
- 移除硬否决后：真缺失≥3 但叠加漏抽半档后总分≥80 者，可能落"合格"。→ 验收须断言"真缺失≥3 全部落 待复核 或 无效"（缺 3 项=64<80→待复核，成立）。
- 逻辑冲突在期望实体缺失时不触发 → 未抽取即漏判（刻意"勿杀"）。
- 重复仅"完全一致"二值 −5，近似重复漏判（实测影响面 0.5%）。
- 一致性仅覆盖 9 证候，12128 种证候写法绝大多数不判。

**边界**
- `reviewUpper <= invalid` 或 `invalid < 0` → 回退基线并告警（`QcRuleStore.normalize`）。
- 权重允许为 0（该项不判）；正则编译失败写路径返 400（保留）。
