## 一、判定口径

「自研组件」= **重复实现了已引入依赖或 Spring 生态已提供的通用能力**，且自研版本在正确性/并发/可维护性上劣于现成方案。判据：

1. 现成实现**已在依赖里**（Redisson / spring-security-crypto / Spring 本体 / MyBatis-Plus）→ 直接换，收益最高。
2. 现成实现需**新增依赖但制品可得** → 可换。
3. 框架**没有等价语义**（如 org 级判权、运行时参数审计、跨实例版本失效）→ 属**领域代码**，不算轮子，保留（§三）。
4. 无调用方 → **删除**，与轮子无关。

## 二、替换项明细

> **注（2026-10-17）**：本节「现状」为**执行前快照**（2026-10-15 取证），各组件的当前状态、行数与实测口径以 §零表 与 §6.9 为准。行数漂移：`RateLimiter` 104→93、`LlmSecretCipher` 143→110、`PythonNlpClient` 194→208、`RegexCache` 58→55、`ExcelRawStreamReader` 310→318、`LlmClient` 428→388、`StatsCache` 281→278、`StatsCacheInvalidator` 38→37、`BatchInsert` 89→83、`AtomicJsonWriter` 70→0（已删）。

### 2.1 `RateLimiter` → Redisson `RRateLimiter`（Wave 1，先做）

- **现状**：`common/utils/RateLimiter.java` 104 行，`RateLimiter(StringRedisTemplate)`（`:60`）。调用方唯一：`AiController.guardAiRate()`（`AiController.java:58-59`），在 `:95 / :150 / :172 / :190` 四处调用。
- **自研了什么**：ZSET 滑动窗口 + 自写 Lua、member 生成与清理、Redis 不可用时 fail-open。
- **替换**：`RedissonClient.getRateLimiter(key)` → `trySetRate(RateType.OVERALL, AI_RATE_LIMIT, Duration)` + `tryAcquire()`。**保留**：Redis 异常时放行（catch `RedisException` → 放行），`RateLimitedException`→429 映射不变。
- **验收**：`RateLimiterTest.java`（实测 **8 个 `@Test`**）改写为针对新原语；`AiController` 行为不变（AI 端点超限仍 429）。
- **风险/语义差异**：`RRateLimiter` 是**令牌桶（固定速率补充）**，原实现是**滑动窗口**；突发流量下允许的瞬时量不同。若验收口径要求"任意 60s 内不超过 N 次"，需在测试里重定口径。

### 2.2 `LlmSecretCipher` → `spring-security-crypto` `Encryptors`（Wave 1）

- **现状**：`common/utils/LlmSecretCipher.java` 143 行，`TRANSFORM = "AES/GCM/NoPadding"`（`:35`），`Cipher.getInstance` 于 `:99-100`（加密）与 `:132-133`（解密），`SecureRandom`（`:40`）、`SecretKeySpec`（`:41`）；密钥来自 `TCM_LLM_ENC_KEY`（env 优先）或 `llm.crypto-key`（`:44-75`），非法时为「未配置」（`available()==false`，保存直接拒绝）。
- **替换**：`Encryptors.delux(password, salt)`（AES-256-GCM，`spring-security-crypto` 已在依赖、当前仅用于 BCrypt）。
- **⚠️ 注意：不是字面替换**：现实现用「原始 32 字节 key」；`Encryptors.delux` 走 **PBKDF2 派生**（password + salt），配置契约与密文格式（`hex(salt):hex(iv‖ct)`）都变。且需**保留两条既有语义**：
  - `available()` → 未配置密钥时**保存直接 503 拒绝**（而非明文落库）；
  - `decrypt` 失败 → **返回空串**（按「未配置」处理，让用户重填），不抛异常。
- **✅ 迁移阻塞已解除（用户 2026-10-15 裁定）**：`llm_config` 当前**仅一个用户使用**，落在库里的旧密文**不需要迁移** —— 换实现后旧密文解不出只会表现为「密钥未配置」，用户在 LLM 设置页**重填一次 Key** 即恢复（这正是 `decrypt` 既有降级路径，`:118-141`）。故 **无需** 旧解密兼容 / 批量重加密脚本。
- **验收**：`LlmSecretCipher` 的加解密 / `available()` / 解密失败返回空 的用例全绿；改完后在设置页重填 Key 一次，跑通一次真实 AI 调用。
- **结论**：**归入 Wave 1**，无迁移负担。唯一要改的契约是「加密密钥」的配置形态（raw key → password+salt），需同步改 `application.yml` / 部署文档。

### 2.4 `VersionedCache` + `RegexCache` → Caffeine（Wave 2）

- **现状**：

### 2.12 摘要 → hex 口径分散在 5 处（**可选，代码卫生**）

- **现状（本轮全仓扫描 `MessageDigest`）**：共 5 处「摘要 → 十六进制」，其中 **3 处是同一能力**（MD5(UTF-8) → 32 位小写 hex）却用了 2 种写法、3 种降级路径：

  | 位置 | 算法 | 转 hex 写法 | `NoSuchAlgorithm` 降级 |
  |------|------|------------|----------------------|
  | `common/utils/RecordUtil.java:120-129` `md5Hex` | MD5 ×16 字节 | `HexFormat.of()` | 抛 `IllegalStateException` |
  | `common/cache/StatsCache.java:265-280` `keyOf` | MD5 ×16 字节 | `String.format("%02x")` 循环 | `digest=""`（所有无筛选请求共用 key） |
  | `service/impl/EsTermIndexServiceImpl.java:402-415` `hashId` | MD5 ×16 字节 | `String.format("%02x")` 循环 | `Integer.toHexString(key.hashCode())` |

  另 2 处**不应合并**：`common/utils/ReviewTaskUtil.java:45-57` `fingerprint`（SHA-256 全 32 字节 → 64 hex）与 `service/impl/DictionaryTermStoreImpl.java:461-471` `contentVersion`（SHA-256 **只取前 16 字节** → 32 hex；长度截断本身是语义）。
- **证伪一条直觉方案**：不要改用 Spring `DigestUtils` 统一口径 —— `javap` 验证 `org.springframework.util.DigestUtils`（`spring-core:7.0.9:compile`，已在依赖树上）**只有 MD5 系列、没有 SHA-256**（仅 `md5Digest` / `md5DigestAsHex` / `appendMd5DigestAsHex` 3 组 6 个方法），覆盖不到上述 2 处 SHA-256，硬换只会制造第 3 套口径。
- **可收敛的部分**：`StatsCache.keyOf` 与 `EsTermIndexServiceImpl.hashId` 改调 `RecordUtil.md5Hex(...)`，删掉两处手写循环（**净减约 10 行**），口径收敛到一处。
  - **必须保留各自的外层 try-catch**：`RecordUtil.md5Hex` 只兜 `NoSuchAlgorithmException`，而 `keyOf` 还要兜 Jackson 序列化失败（`objectMapper.writeValueAsString`）、`hashId` 的 catch 包着整个方法体。三者降级返回**互不相同**（`""` / `hashCode()` / 走不到），这是有意的业务取舍，不能一并统一。
  - **输出等价性已实测**：`HexFormat` / `printf %02x` / `DigestUtils.md5DigestAsHex` 三种写法对 `""`、`"abc"`、`"中医电子病历"`、`"舌红苔白，脉弦"`、`"null"`、`"a\u0000b\u0000c"` 6 个样本**逐字节一致**（`Dg3` 探针）→ 收敛**无行为变更**。
- **处置建议**：定 **P3 / 代码卫生、非缺陷**（三处输出本就一致，不影响正确性）→ 列为 Wave 1 的**可选附加项**，随 #3 / #10 顺手做；不做也不留验证缺口。

## 七、执行手册（可直接照做）

> **⚠️ 本手册为 2026-10-15 执行前所写，其中 #1/#2/#3 的步骤与实测落地有偏差**，以代码与 commit 为准：**#1** 语义实测**等价滑动窗口**（非「令牌桶换滑动窗口后重定口径」），且每次调用须 `trySetRate` + `expire(window)` + `tryAcquire` 三步（TTL 不补则 key 永不过期）；**#2** 配置键为 `llm.crypto-password` / `llm.crypto-salt`（env `TCM_LLM_ENC_KEY` / `TCM_LLM_ENC_SALT`，盐须偶数长度 hex），空口令须自行校验；**#3** 需**两个** `RestClient`（抽取 30s / 探测 2s，JDK 请求工厂读超时是工厂级），传输层仍 `JdkClientHttpRequestFactory` + HTTP/1.1。偏差明细见 §6.9。
