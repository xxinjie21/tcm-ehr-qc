## 二、你的诉求与设计原则（先确认，全篇按此执行）

1. **相同功能用同一个组件模型**：相似功能（如范围查询）必须复用同一组件，跨页放**同一位置**、**外形统一**。
2. **不等高必须修**：页面内并列组件内容等高；"本范围扣分构成" vs "AI 预检列表/扣分明细"是最典型的一处。
3. **范围查询是共用组件**：它不属于任何一张卡，是整页/整条共享的查询。
4. **美观 = 调位置、不动颜色**：不改变现有配色，只调整组件位置/间距让操作顺手。
5. **加载组件**：必须有动态效果，且**位置不遮盖原有文字/内容**（不重合）。
6. **滚动条最少化**：能在一页内放下就不滚动；只有"操作导致内容变长"才需要滚动。
7. **组件内部留白**（非页面留白）需逐组件审查并标准化。

## 三、逐项发现（含图片地址 + 代码证据）

### A. 不等高问题 —— 你点名的核心问题（未彻底修复）

**现象（截图）**：`docs/visual-bench/屏幕截图 2026-10-17 195220.png`（质控校验页）。
左侧"本范围扣分构成"与右侧"AI 预检列表"内容段不等高，短的一栏在卡底留空白、两卡底边不齐。

**代码现状**：
- `frontend/src/views/Qc.vue:102` `.grid-2` 并排两卡；`:121/:163` 两表用 `useFillTableHeight` 反算定高（`frontend/src/composables/useFillTableHeight.js`，依赖 ResizeObserver + 逐层测量，**脆弱的 JS 方案**）。
- `Qc.vue:846-893`：等高只在 `:deep(.panel:first-child)` 上做 flex 撑满，`@media (max-width:1599px)` 时**塌成单列**——1366 档根本看不到侧排等高。
- 同风险页面：`NlpExtract.vue:820/834/840` 也是 `minmax(0,…)` 分栏，一样可能不等高。

**改法**：改用 **CSS grid `align-items: stretch` 双卡默认拉伸** + 两卡都 `flex-column` 让正文吃满；短内容用 `justify-content: safe center` 居中。移除对 `useFillTableHeight` 的 JS 依赖（或降级）。等高行为抽成复用组件 `EqualHeightPanels`。

### B. 范围查询归属 + 组件统一 —— 你点名的第二个核心问题

**现象**：源码里筛选条其实已在顶部共享（`Qc.vue:19-97` `.scope-bar`，注释明确"范围对扣分构成与 AI 预检列表同时生效"），
但**"本范围扣分构成"标题以"本范围"开头，语义上把共享筛选读成了"只属于这张卡"**；且筛选条内混进"质控评分计算/取消重算"等页面动作，视觉上仍像"扣分构成卡的工具条"。

**代码现状（组件不统一）**：
- **筛选家族两个组件、外形不一致**：
  - `frontend/src/components/RangeFilter.vue`（受控 v-model）：科室 140px + 就诊 daterange 240px + 导入时间 240px + 分级 110px，**不含查询/重置按钮**。**已被 7 处复用**：Records、Qc、Review、Governance、NlpExtract、StandardizationReport、NlpBatchPanel。
  - `frontend/src/components/StatsFilter.vue`（事件驱动）：开单科室 150px + 就诊起始/截止两个单日期 150px，**自带查询/重置**。**仅 Dashboard 在用**（`Dashboard.vue:130`）——是筛选家族唯一不统一的点。
- **跨页位置不一致**：
  - Dashboard（`195132.png`）：筛选 y≈150，StatsFilter。
  - Records（`195139.png`）：y≈185，RangeFilter + 自带按钮。
  - Qc（`195220.png`）：y≈170，RangeFilter + 质控评分/重算。
  - Review（`195230.png`）：y≈160，RangeFilter + 查询/重置。
  - Governance（`195309.png`）：y≈160，RangeFilter。
  - StandardizationReport（`StandardizationReport.vue:33-42`）：筛选**嵌在报告头卡内**（rh-tools），非独立条。

**改法**：
1. 合并为一套 `RangeFilter`（受控），StatsFilter 的能力并入；外观、宽度、字段顺序统一。
2. 定义统一位置：**筛选条固定在每页内容区最上方、全宽、紧贴第一个面板之前**，六页同一形态。
3. 页面专属动作（重算、删除、清洗、导出）**移出筛选条**，放面板头/独立动作区。

### C. 操作动线（深挖后新增两处问题）

**现状（主流程顺畅）**：Dashboard 指标卡可点击下钻（`Dashboard.vue:86`）；Review"进入复核"内联展开（`ReviewDetailPanel.vue`）；扣分明细走弹窗（`QcDeductionDialog.vue`）。✓

**问题 1：多页"两套筛选并存"，动线有摩擦**
- **Review 页（`Review.vue:7-12 / 28-41`）**：顶部 RangeFilter（范围）+ 待复核列表卡内 `状态`下拉 + `只看超期未复核` checkbox。用户要在**两个位置**维护筛选状态：范围在上、状态在卡内——动线割裂。截图 `195230.png` 可见。
- **Qc 页（`Qc.vue:19-97`）**：筛选条里混了 `质控评分计算` 这个**动作**，用户第一眼分不清"这是查询还是操作"。

**问题 2：破坏性/批量操作与共享筛选条混排**
- Qc 的重算、Records 的批量删除、Governance 的执行清洗，都紧贴/混在筛选区。用户需要"查询→确认范围→再找操作"，动线不清晰。

**改法**：
1. 每页**主操作固定在同一角落**（内容区右上，与面包屑对齐）。
2. 批量/破坏性动作**独立成区**、加确认，与筛选条彻底分离。
3. 一页只保留**一套筛选心智**：范围（RangeFilter）统一在顶部；卡内次级筛选（如状态）保持与范围同轴、位置固定。

**现象**：同一个项目里**三种加载范式**，多数是遮罩压字，与你的要求冲突。

**范式一：`v-loading` 全容器遮罩（✗ 压住原内容，11 处）**
`AuditLog.vue:52`、`Dictionary.vue:62`、`Dashboard.vue:42`、`Groups.vue:6`、`Review.vue:44`、`Qc.vue:104`（扣分构成）、`LlmConfigDialog.vue:32`、`RecordActivityTimeline.vue:5`、`ReviewDetailPanel.vue:2`、`MyGroup.vue:11`、`RecordTable.vue:20`。
→ Element 遮罩盖住容器内已有文字/内容，正是你明确反对的"重合"。

**范式二：行内小圈 `.spin-inline`（✓ 已做对）**
`Governance.vue:14/18/653`，注释写明"原 v-loading 整块遮罩压住了数字，改行内小圈"。

**范式三：骨架屏（✓ 已做对、有动态效果，但没抽成共享组件）**

→ 两处各自实现一份骨架屏，**未抽取**为共享 `LoadingSkeleton`，属于"重复实现"。

### E. 滚动条

**现状**：
- 页面级：`MainLayout.vue:659-663` `main { overflow-y:auto }` + `.layout` 定高隐藏 → **文档不滚、只 main 内单滚**，做对了 ✓。
- **横向滚动（问题）**：Qc 右卡"AI 预检列表"列宽合计 ~716px、卡宽仅 ~660px → 表内横向滚动（`Qc.vue:848-852` 自认）；`DictionaryImport.vue:1309` `overflow-x:auto`。

**改法**：
1. 消除表格横向滚动：压缩/合并低价值列、列允许收缩、长文本 `show-overflow-tooltip`（RecordTable 已示范）。让 Qc 右表、NlpExtract 选择器单屏放下。

3. 保留 main 底部 84px 呼吸留白（`MainLayout.vue:723`）✓。

### K. 输入框大小一致性（实测 + 全量代码核实）

**根因**：`App.vue:4` 的 `el-config-provider` 只下发 `:locale="zhCn"`，**未下发全局 `:size`**。`theme.css:78-80` 虽已定义控件尺寸令牌（`--el-component-size-small/md/large` = `--ctl-h-sm/md/lg`），但**没有一个生效入口**（Element Plus 缺全局 size 时回落 default ≈40px）。于是各处 `size=` 与字面量宽度**各自为政**：

**① 控件 size 三档混排（同一页内都有）**：
- `size="large"`(40px)：仅 `NlpExtract.vue:163` 右侧详情表单（注释明说"控件尺寸统一由 size=large 决定 40px"）。
- 默认(40px)：各筛选条/表单项。
- `size="small"`(≈32px)：`NlpExtract.vue:279/284/291` 左侧选择/归一区（词典类型 116px）、`Governance.vue:185` 导出 select、`Dictionary.vue:31/46` 词典类型、各表 `el-table size=small` 内联控件。
- → **NlpExtract 一页里左栏 32px、右栏 40px 并存**，是"输入框大小"最直观的实例。

**② 同一「科室」筛选三种宽度（跨页）**：
- `RangeFilter.vue` 科室 140px；`StatsFilter.vue`（Dashboard）科室 150px；`Governance.vue:185` 导出 `ex-department` 130px。
- 就诊/导入时间同理：RangeFilter daterange 240px vs StatsFilter 单日期 150px×2。

**③ Governance 同页两套范围查询**：清洗区用 `rf-*`（RangeFilter），导出区用 `ex-*`（自写 130px）——同一功能一页两实现、两尺寸。

**④ 其它宽度硬编码**：Review 状态下拉 130px（`Review.vue:32`）、QcRules 内 el-select 120px / elementNames `min-width:320px`、AuditLog 操作类型 150px。

**改法**：
1. **`App.vue` 的 el-config-provider 下发全局 `:size="default"`**（或统一 medium），让 Element Plus 控件尺寸全局收敛；个别大表单（NlpExtract 详情）用局部 size 覆盖并注明例外。
2. **统一筛选字段宽度为一套令牌档**（如科室 150px、日期 240px、分级 110px），由 `RangeFilter` 收敛（含并入的 StatsFilter 字段）。
3. Governance 导出区 `ex-*` 收敛为 RangeFilter（或同一宽度规范），消除同页两套。
4. 小表单/弹窗内输入控件统一 default 或 small 档，不再混排；字号随 size 走（避免 `theme.css:440` 所述 small 字号写死 12px 的坑）。
