## 五、已知限制

1. **词典路径**：`application.yml` 的 `dictionary.dir` 为绝对路径（换机器需修改）。
2. **IK自定义词典**：当前依靠"别名全量入库+ik_max_word"匹配；IK ext_dict 未配置（动态热更新需 remote_ext_dict HTTP 方案，可作增强项）。
3. **score阈值**：`elasticsearch.score-threshold=0.8` 为 BM25 经验值；标准词精确命中不走阈值（零误判），阈值仅约束模糊路径。
4. **清洗策略**：重复/异常数据仅标记 `status=invalid` 不物理删除，保证可追溯。
5. **stats聚合**：500条级内存聚合（<50ms）；数据量到万级建议改 MySQL JSON_TABLE 或定期物化。
6. **formulas词典仅5条**：数据中处方为草药组合（无方剂名），按核心药组合规则（7首经典方）推断，可后续导入扩充。

## 八、归一化与治理页重构（第三轮）

通读全部设计文档（需求分析/功能设计/项目设计/openapi）后，按文档定义修正：

### 8.1 归一算法重构（修复"咽喉痛→腰部冷痛"误命中bug）
- **根因**：ES BM25对短中文词仅共享单字（"痛"）即超阈值误命中；且ES的minimum_should_match百分比在小token数下取整后失效
- **修正**：按项目设计文档9.4算法实现——①精确（标准词/别名全等）→②**双向包含**（输入包含别名 或 别名包含输入）→③**字符Dice相似度≥0.8**（"咽喉痛"vs"腰部冷痛"=0.29拒绝；vs"咽痛"=0.8命中；"膝关节疼"→"膝关节疼痛"=0.89命中）
- 实测：无关词正确返回原词+空source；双向包含"腰冷痛"→"腰部冷痛"生效

### 8.2 清洗算法对齐文档5步流水线（9.5节）
`执行数据清洗` = ①去重（**原始文本哈希**，替换原挂号号方案）→ ②字段修补（trim/空值）→ ③格式规整 → ④脏数据隔离 → ⑤**术语自动归一**（遍历合格病历structuredData全实体，content替换为国标标准词、sourceText保留原文溯源，`normalized`计数）——归一完成后`governed`标记置1

### 8.3 治理页UI对齐原型（项目设计文档第8节5）
- 移除错位的"术语标准化"手动查词面板（normalize接口保留供NLP链路/复核修正内部调用）
- 新增顶部状态行：质控合格/待治理/已治理（GET /api/governance/stats，records表新增`governed`列）
- 导出筛选对齐查询1字段：科室/dateRange/证候（TermInput自动补全）
- 新增**[预览数据集]**：POST /api/export/dataset/preview（总数+前10条样本）
