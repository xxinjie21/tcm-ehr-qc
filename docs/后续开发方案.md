### 2.5 线B-4：AI质控评分（分数真实化）

**后端算法**

| 模块 | 设计 |
|------|------|
| `common/utils/QcScorer.java` | **判空规则**：核心字段按 structured_data 非空判断<br>structured 为空再回退查原始列（pulse/tongue/pattern/prescription）<br>两者皆空才判缺失 |
| 三层扣分 | ① 核心缺失各 -15（脉象/舌象/证候/治法/方剂/中药，共6项）<br>② 逻辑冲突各 -10（证候-治法 / 证候-方剂 / 证候-中药）<br>③ 格式+重复+症状为空 各 -5（age 非数字 / 性别非男女 / 文本MD5重复 / symptoms 为空） |
| 严重判定 | 核心缺失 ≥3；证候-治法与证候-方剂同时冲突；文本无法解析 → 直接 invalid；`score = max(0)` |
| 分级路由 | ≥90 且无逻辑冲突 → 合格<br>60~89 分或存在逻辑冲突 → 待复核<br>60 分以下或严重问题 → 无效 |
| `common/utils/LogicChecker.java` | 证候→治法→方剂规则（固定写死、不支持自编辑）：<br>· 风寒感冒 → 辛温解表 → 麻黄汤/桂枝汤<br>· 风热感冒 → 辛凉解表 → 银翘散/桑菊饮<br>· 暑湿感冒 → 清暑祛湿 → 新加香薷饮<br>舌脉规则：舌红×脉沉迟、舌淡×脉数 → conflict<br>**未覆盖证候不判冲突（不误杀）** |

**接口**

| 接口 | 说明 |
|------|------|
| `POST /api/qc/score` | 单条评分，入参 `QcScoreDTO`（结构化数据），返回 `ScoreResultVO` |
| `POST /api/qc/score/batch` | 全库重算（事务 + 逐条幂等），返回分级分布；批量前清理旧 review_tasks(pending) |

**`ScoreResultVO` 与 `qc_results` 写入结构（可溯源）**
```json
{
  "score": 75,
  "grade": "待复核",
  "deductions": [
    {"type": "核心字段缺失", "item": "脉象", "points": 15, "reason": "pulseList 与 pulse 均为空"},
    {"type": "逻辑冲突", "item": "证候-方剂", "points": 10, "reason": "风寒感冒 不匹配 银翘散"}
  ],
  "logicConflicts": ["证候-方剂不匹配：风寒感冒 × 银翘散"],
  "serious": false,
  "checkedAt": "2026-09-17 10:00:00"
}
```

**前端重算入口**

| 项 | 明细 |
|----|------|
| 位置 | `Governance.vue` 治理状态行右侧「**质控评分重算**」按钮（仅管理员可见） |
| 交互 | 点击 → confirm（"将按质控规则对全库重算评分与分级，覆盖现有分数，确认？"）→ loading → 提示新分布 → 刷新治理状态行 + 看板 |
| 失败态 | 401/500 统一错误提示；接口未开通时按钮置灰 + tooltip"后端预留" |
| mock 形态 | 审核阶段按钮先用假分布演示（真实接口由后端提供） |

**与现有链路联动**
- 重算后看板 overview 数字自动正确；导出/预览只导"真实合格"（范围变化属预期）；`governed` 保持现状不重置；
- 待复核病历自动生成 `review_tasks`（pending，deadline=+7 工作日）到数据层（UI 属线C待定）；
- 性能：500 条内存循环 + 词典查询，预计 1s 内；重复调用结果一致（幂等）。

**验收标准**：batch 后分级分布合理（非 85/12/3 随机）；抽查 `qc_results` 扣分明细与 score 一致；border 例（60/90 分）路由正确。
