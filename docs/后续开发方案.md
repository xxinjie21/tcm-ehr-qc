### 1.3 数据规模化（≥3 万条真实数据）

> 真实病历规模 ≥3 万，替换原"500 条内存假设"，全链路数据访问采用 **SQL 优先**。

| 环节 | 规模化要求 |
|------|-----------|
| 过滤 / 分页 | `RecordFilter` 改 **QueryWrapper 条件 + selectPage 分页**（SQL），不再全表内存过滤；仅小范围子集可用内存 |
| 清洗 / 批量重算 | **分页游标分批**（每批 500~1000），逐批提交 + **单条本地事务** + 失败清单累计（见批B·2.3） |
| 统计 / 图谱 | **SQL GROUP BY + JSON 函数 + LIMIT**（topN：图谱节点 200 / 边 800，**yml 可配置** `qc.graph.max-nodes / max-edges`，默认不变），不逐个病历内存解析 |
| 导出 | **流式**：CSV 逐行输出 / JSON Jackson streaming，3 万可导出；**\>万条导出 → 二期改异步**（生成文件 + 下载链接）；v1 仅子集 / 流式同步导出 |
| 互斥 | EX 900s（对齐批时长）；`FilterUtils` 统一 hash（见 §8.7） |
| 索引 | 补 `(department, visit_time)` 复合索引（见 §5.3） |
| 性能基准 | 3 万全量重算 ≤3min；单页查询 ≤300ms；统计 / 概览 ≤2s |
| 验证数据 | 新增 `tools/seed-30k.py`（**性能验证用，非演示数据**，与 seed-500 演示基线区分） |

#### 批A · 1.4 术语库导入增强（④ 混合方案）

- **目的**　：国标 PDF 免手工转 JSON（兑现"LLM 即 ETL"），断网走离线路径。
- **改动点**：下表。
- **开发流程**：后端 convert / JSON 直传 → 前端 Dictionary.vue PDF/JSON → build + 手工验证。
- **验收标准**：PDF+LLM 预览→确认入库；JSON 直传；断网兜底。

> 目标：**国标 PDF 免手工转 JSON**，兑现功能设计第16节「LLM 即 ETL」；断网仍可走离线路径。

| 子项 | 做法 |
|------|------|
| 系统主链路 | `POST /api/dictionary/convert`：上传 `.pdf` → PDFBox 抽文本 → 调 LLM 转换（Prompt 提取 standardTerm/aliases，仅返回 JSON，同文档16节）→ 返回候选条目预览 → 管理员确认 → `POST /api/dictionary/import` 写入 |
| JSON 直传 | `import` 支持 `.json`（TermEntry 数组 `[{standardTerm, aliases[], source?, code?}]`，**`code` 为可选国标代码（GB/T 15657 / GB/T 16751）**，校验+去重合并别名）；Excel/CSV 支持可选第 3 列「代码」；前端 `accept=".xlsx,.xls,.csv,.json"` |
| LLM 通道 | 新增 **`common/utils/LlmClient.java`**（**双 provider**：`local=Ollama` / `cloud=OpenAI 兼容`；**供 ②convert ③chat ④interpret ⑤review ⑥report 统一复用**）→ 词典转换 `/api/nlp/convert`；开关 `llm.enabled` 总控 + `nlp.convert-enabled` 子控（默认 false）；关闭时 PDF 上传返回友好提示（走离线脚本 / JSON 直传） |
| 离线脚本 | `tools/convert-standard-pdf.py`（python pdfplumber 抽表格 → 组 standardTerm/aliases/source → 出 5 类 JSON → 打印校对清单）；老师提供真实国标 PDF 时跑一次，产物可直接 JSON 直传 |
| 依赖 | 后端加 `org.apache.pdfbox:pdfbox`；脚本需 Python `pdfplumber` |
| 预览确认 | `ConvertPreviewVO {type, candidates:[{standardTerm, aliases, source?, code?}], failed:[{text, reason}]}`（**failed 含原因**，方便定位无法提取的文本）；确认后再 import，失败明细可下载 |
| 验收 | LLM 开关开：PDF→预览→确认入库全通；JSON 直传成功；断网（开关关）：PDF 兜底提示；.xls 复验通过 |

#### 批B · 2.3 AI质控评分（分数真实化）

- **目的**　：按文档9.2 实现真实评分（calculateScore），替代随机分数。
- **改动点**：QcScorer / LogicChecker / QcController / batch 重算入口 / qc_results 预检单。
- **开发流程**：重算入口前端先行 预览桩 → 审核 → 后端评分 → batch 重算验证。
- **验收标准**：batch 后分级分布合理（非 85/12/3 随机）；抽查 `qc_results` 扣分明细与 score 一致；border 例（60/90 分）路由正确。

**后端算法**

| 模块 | 设计 |
|------|------|
| `common/utils/QcScorer.java` | **判空规则**：核心字段按 structured_data 非空判断<br>structured 为空再回退查原始列（pulse/tongue/pattern/prescription）<br>两者皆空才判缺失 |
| 三层扣分 | ① 核心缺失各 -15（脉象/舌象/证候/治法/方剂/中药，共6项）<br>② 逻辑冲突各 -10（证候-治法 / 证候-方剂 / 证候-中药）<br>③ 格式+重复+症状为空 各 -5（age 非数字 / 性别非男女 / 文本MD5重复 / symptoms 为空） |
| 严重判定 | 核心缺失 ≥3；证候-治法与证候-方剂同时冲突；文本无法解析（三者之一命中）→ **直接 invalid**：分数**保留扣完值**（`score=max(0,扣完)`）**仅用于统计**，`grade="无效"`、`serious=true`；**分级与分数独立判定**，不因 invalid 强制归零 |
| 分级路由 | ≥90 且无逻辑冲突 → 合格<br>60~89 分或存在逻辑冲突 → 待复核<br>60 分以下或严重问题 → 无效 |
| `common/utils/LogicChecker.java` | 证候→治法→方剂规则（固定写死、不支持自编辑）：<br>· 风寒感冒 → 辛温解表 → 麻黄汤/桂枝汤<br>· 风热感冒 → 辛凉解表 → 银翘散/桑菊饮<br>· 暑湿感冒 → 清暑祛湿 → 新加香薷饮<br>舌脉规则：舌红×脉沉迟、舌淡×脉数 → conflict<br>“**当前版本=演示版硬编码规则；可扩展路线=迁移数据库规则表（本版本不做，记录待办）**“<br>**未覆盖证候不判冲突（不误杀）** |

**接口**

| 接口 | 说明 |
|------|------|
| `POST /api/qc/score` | 单条评分，入参 `QcScoreDTO`（结构化数据），返回 `ScoreResultVO` |
| `POST /api/qc/score/batch` | 全库/范围内重算（**分页分批 + 单条本地事务**，见 §1.3），返回分级分布 + **失败清单**；**无批量前置清理**（review_tasks 由单条幂等 upsert 收敛，见下）；**上限 `qc.batch.max-records`（默认 3 万，yml 可配）**：超限返回 400「超过单次上限，请缩小范围或子集操作」，前端超范围提示分片 / 子集 |

**`ScoreResultVO` 与 `qc_results` 写入结构（可溯源）**
```json
{
 "score": 75,
 "grade": "待复核",
 "deductions": [
 {"type": "核心字段缺失", "item": "脉象", "points": 15, "reason": "pulseList 与 pulse 均为空"},
 {"type": "逻辑冲突", "item": "证候-方剂", "points": 10, "reason": "风寒感冒 不匹配 银翘散"}
 ],
 "logicConflicts": ["证候-方剂不匹配：风寒感冒 × 银翘散"],
 "serious": false,
 "checkedAt": "2026-09-17 10:00:00"
}
```

**前端重算入口**

| 项 | 明细 |
|----|------|
| 位置 | `Governance.vue` 治理状态行右侧「**质控评分重算**」按钮（仅管理员可见） |
| 交互 | 点击 → confirm（"将按质控规则对全库重算评分与分级，覆盖现有分数，确认？"）→ loading → 提示新分布 → 刷新治理状态行 + 看板 |
| 失败态 | 401/500 统一错误提示；接口未开通时按钮置灰 + tooltip"后端预留" |
| 预览形态 | 审核期预览桩 → 后端接口就绪后**切真**，页面不保留假分布 |

**与现有链路联动（含 review_tasks 一致性与事务）**
- 重算后看板 overview 数字自动正确；导出/预览只导"真实合格"（范围变化属预期）；`governed` 保持现状不重置；
- **review_tasks 幂等 upsert（单条事务内）**：`grade=待复核` → 该病历已有非 obsolete 任务则**更新**（issueType/score），否则**新建**（deadline=+7 工作日）；`grade≠待复核` → 该病历 pending 任务置 **`is_obsolete=true`**；**无批量前置清理**，规避事务外删除竞态；查询统一过滤 `is_obsolete=false`；
- 状态一致性（U16）：待复核病历 `records.status` 同步置 `reviewing`，避免看板 `pendingReviewCount(status)` 与"待复核"口径不一致；
- **事务边界**：外层不包全局事务；单条=本地事务（评分+写 records+review_tasks 原子）；异常→记失败 ID、跳过并汇总失败清单（不回滚整体、不自动重试）；配合分页分工（§1.3）；
- **部分成功语义（加粗）**：失败病历**不回滚已写入的 qc_results / review_tasks**（幂等、可溯源），仅返回失败清单；
- **batch 任务日志**：执行后写一条 `operation_log`（任务类型 / 筛选范围 / 总数 / 成功数 / 失败数；失败明细返回前端，日志记"失败数 + 前 N 条示例"防超长）；
- 性能：分批 SQL 运行（见 §1.3），3 万全量 ≤3min；重复调用结果一致（幂等）。

| 实验 | 做法 | 产出 |
|------|------|------|
| 人机一致性评估 | 至少 **20 份待复核病历**，每份 ≥2 名审核员**独立标注、互不互通结果** | 吻合率 + **Cohen's Kappa**（AI=A、人工主审=B；多人可扩展 Fleiss' Kappa）+ 三级混淆矩阵；**注明小样本 20 置信区间弱、结论仅作演示；Kappa 只统计「规则初检分级 vs 人工复核」，LLM 预检意见不参与计算** |

- **固定提示**：评估报告页顶部常驻「**演示数据结论，非正式临床验证**」；
- **小样本三处标注**：代码注释 / 评估报告 / openapi 统一注明"样本 20、置信区间弱、仅作演示"；
- 结论要求：数据 → 图表 → 结论 → 局限；
- **实验结论 LLM 撰写（F）**：`/api/ai/report`（LlmClient）基于 Kappa / 命中分布数字生成"数据 → 结论 → 局限"实验说明段落；**仅叙述、不做判定**；LLM 不可用 → 保留规则结论文本。

## 7. 注意点

| 注意点 | 处理 |
|--------|------|
| 重算后合格数量可能剧变（441 大跌） | 属预期；口径统一"评分规则真实化" |
| checkLogic 规则仅3条（覆盖率窄） | 写死不支持自编辑；未覆盖证候不判冲突（不误杀） |

## 8. 开发规范与协作

### 8.1 后端规范

- **分层**：`common`（config/domain/exception/interceptors/utils）+ `controller` + `domain`（dto/po/vo）+ `mapper` + `service`（接口）+ `service/impl`（实现）；
- **命名**：`I*Service` 接口 + `*ServiceImpl` 实现（`@Service`）；绑表服务 `extends IService<Po>` / `ServiceImpl<Mapper,Po>`；
- **响应**：统一 `Result{code,msg,data}`，文件流接口（导出/日志）除外；
- **异常**：业务异常由 `GlobalExceptionHandler` 统一出口（401 / 400 / 500 → Result），**Controller 禁止 try-catch 兜错**；
- **留痕**：清洗 / 导出 / 导入 / 回滚 / 复核等关键操作调用 `OperationLogger` 写 `logs/operation.log`；
- **鉴权**：JWT（`JwtInterceptor`），放行 login / register。

### 8.2 前端规范

- **主题**：中式变量 `--ink/--paper/--line/--ochre/--danger`（见 `theme.css`），不加渐变 / emoji / 骨架滚动动画；
- **组件复用**：PanelCard / StatCard / BarList / TermInput / StatsFilter→RangeFilter / StructuredDataCard（新增），优先复用不新建；
- **请求**：统一走 `utils/request`（响应拦截 + blob 下载 `utils/download`）；接口封装于 `api/*.js`；
- **预览桩 定位（收紧）**：仅用于审核预览，**不上运行页**；合 main 前切真；接口未就绪用空态提示、不显示假数据；
- **契约对齐**：预览桩数据结构**必须与 openapi VO 完全对齐**（字段名/类型一致），仅填假值、不增删字段；

### 8.3 契约纪律

- 新增 / 变更接口：**先更新 openapi.yaml，再实现代码**；响应字段以 openapi 为准；
- 错误码查 openapi 附录B（2001 / 4001 / 1006 / 2003 等）；前置校验统一 `IllegalArgumentException` → HTTP 400。

### 8.4 git 工作流

- 每线独立 commit、可独立回滚；commit 格式 `feat|fix|docs|refactor(scope): 描述`；
- 前端先行：本批任务前端（预览桩）提交审核通过后，方可做该任务后端；
- **分支模型**：仓库维护 4 个长期分支——`main`（基线 / 合入目标）+ `XXJ` / `YC` / `ZRC`（三个成员各自的开发分支），全部使用、不删除、不过期；任务在各自分支开发，审核通过后合入 main；分支定期同步 main，避免长期分叉。
- **MR 流程**：开发分支完成任务 → **提交 MR 到 main → 代码评审 + 验收测试通过 → merge**；main 保持随时可演示状态；**预览桩 / 静态假数据文件（如 graph-preview.js）须在切真接口、MR 合入前删除，不得留在代码仓库**；
- **MR 检查项**：合 main 前执行 `grep -rn "graph-preview|静态假数据" src/` 扫描，禁止预览桩数据文件合入；
- **菜单动态渲染**：评审 / MR 前前端菜单必须按登录角色**动态渲染**，**不得硬编码全开**；仅演示截图可临时以管理员账号截图；

### 8.7 并发防护约定

- **原则**：单实例部署，不使用分布式锁（Redisson）；采用「幂等 + 轻量任务互斥」；
- **任务互斥**：全库写操作（质控重算 batch / 数据清洗 clean）执行前用 Redis `SETNX tcm:task:{type}:{filtersHash} NX EX 900`（复用已有 RedisTemplate `setIfAbsent(key, value, Duration)`，`filtersHash`=FilterUtils 固定 key 排序 JSON 的 MD5）抢占；**同范围互斥、不同范围可并行**；占用中返回"任务进行中"；成功后 `DEL`；**锁生命周期：EX 900s 为兜底防死锁；正常完成在 finally 中 DEL 主动释放；进程异常退出由 EX 自动过期兜底**；**风险备注：若任务超过 EX，锁自动过期 → 允许提交新 batch = 并发风险；3 万全量 ≤3min 早于 900s 释放、余量充足；数据再膨胀 → 升级二期「任务持久化表 + 状态机」**；
- **执行时长监控**：任务执行时长 ≥ EX 85%（≈765s）打印 **warn 日志**进操作日志；前端同步接口显示「执行中（当前范围：…）」+ 预计文案，**实时进度条属二期异步改造**（v1 同步接口无法轮询）；数据膨胀超阈值 → 二期异步任务表 + 状态机（明确待办，不再依赖简单 SETNX）;
- **幂等**：batch / clean 重复调用结果一致（review_tasks 由单条幂等 upsert 收敛、无前置批量清理，见 批B·2.3）；
- **词典文件**：导入 / 回滚 / 备份方法加 JVM 锁（synchronized），避免并发覆盖词典 JSON 与 ES 索引重建冲突；**仅单机生效；多实例部署需替换为 Redis 分布式锁（扩展预留已列）**；
- **扩展预留**：若未来扩展多实例部署，可将 SETNX 互斥升级为 Redisson 分布式锁（注明适用边界后再引依赖）。

### 8.8 角色鉴权约定

| 角色 | 菜单 | 接口权限 |
|------|------|---------|
| 管理员 | 8 项全量（首页/病历/结构化解析/质控校验/复核/清洗导出/词典/审计） | 全部（含治理/词典/质控/导出 等管理操作） |
