#### 批A · 1.4 术语库导入增强（④ 混合方案）

- **目的**　：国标 PDF 免手工转 JSON（兑现"LLM 即 ETL"），断网走离线路径。
- **改动点**：下表。
- **开发流程**：后端 convert / JSON 直传 → 前端 Dictionary.vue PDF/JSON → build + 手工验证。
- **验收标准**：PDF+LLM 预览→确认入库；JSON 直传；断网兜底。

> 目标：**国标 PDF 免手工转 JSON**，兑现功能设计第16节「LLM 即 ETL」；断网仍可走离线路径。

| 子项 | 做法 |
|------|------|
| 系统主链路 | `POST /api/dictionary/convert`：上传 `.pdf` → PDFBox 抽文本 → 调 LLM 转换（Prompt 提取 standardTerm/aliases，仅返回 JSON，同文档16节）→ 返回候选条目预览 → 管理员确认 → `POST /api/dictionary/import` 写入 |
| JSON 直传 | `import` 支持 `.json`（TermEntry 数组 `[{standardTerm, aliases[], source?}]`，校验+去重合并别名）；前端 `accept=".xlsx,.xls,.csv,.json"` |
| LLM 通道 | 新增 `common/utils/LlmConversionClient.java`（复用 PythonNlpClient 式 HTTP 封装，指向 NLP 服务 `/api/nlp/convert`）；开关 `nlp.convert-enabled` 默认 false；关闭时 PDF 上传返回友好提示（走离线脚本 / JSON 直传） |
| 离线脚本 | `tools/convert-standard-pdf.py`（python pdfplumber 抽表格 → 组 standardTerm/aliases/source → 出 5 类 JSON → 打印校对清单）；老师提供真实国标 PDF 时跑一次，产物可直接 JSON 直传 |
| 依赖 | 后端加 `org.apache.pdfbox:pdfbox`；脚本需 Python `pdfplumber` |
| 预览确认 | `ConvertPreviewVO {type, candidates:[{standardTerm, aliases, source}], failed}`；确认后再 import，失败明细可下载 |
| 验收 | LLM 开关开：PDF→预览→确认入库全通；JSON 直传成功；断网（开关关）：PDF 兜底提示；.xls 复验通过 |

#### 批B · 2.3 AI质控评分（分数真实化）

- **目的**　：按文档9.2 实现真实评分（calculateScore），替代随机分数。
- **改动点**：QcScorer / LogicChecker / QcController / batch 重算入口 / qc_results 预检单。
- **开发流程**：重算入口前端先行 mock → 审核 → 后端评分 → batch 重算验证。
- **验收标准**：分布非随机；扣分明细可溯源；border（60 / 90）路由正确。

**后端算法**

| 模块 | 设计 |
|------|------|
| `common/utils/QcScorer.java` | **判空规则**：核心字段按 structured_data 非空判断<br>structured 为空再回退查原始列（pulse/tongue/pattern/prescription）<br>两者皆空才判缺失 |
| 三层扣分 | ① 核心缺失各 -15（脉象/舌象/证候/治法/方剂/中药，共6项）<br>② 逻辑冲突各 -10（证候-治法 / 证候-方剂 / 证候-中药）<br>③ 格式+重复+症状为空 各 -5（age 非数字 / 性别非男女 / 文本MD5重复 / symptoms 为空） |
| 严重判定 | 核心缺失 ≥3；证候-治法与证候-方剂同时冲突；文本无法解析 → 直接 invalid；`score = max(0)` |
| 分级路由 | ≥90 且无逻辑冲突 → 合格<br>60~89 分或存在逻辑冲突 → 待复核<br>60 分以下或严重问题 → 无效 |
| `common/utils/LogicChecker.java` | 证候→治法→方剂规则（固定写死、不支持自编辑）：<br>· 风寒感冒 → 辛温解表 → 麻黄汤/桂枝汤<br>· 风热感冒 → 辛凉解表 → 银翘散/桑菊饮<br>· 暑湿感冒 → 清暑祛湿 → 新加香薷饮<br>舌脉规则：舌红×脉沉迟、舌淡×脉数 → conflict<br>**未覆盖证候不判冲突（不误杀）** |

**接口**

| 接口 | 说明 |
|------|------|
| `POST /api/qc/score` | 单条评分，入参 `QcScoreDTO`（结构化数据），返回 `ScoreResultVO` |
| `POST /api/qc/score/batch` | 全库重算（事务 + 逐条幂等），返回分级分布；批量前清理旧 review_tasks(pending) |

**`ScoreResultVO` 与 `qc_results` 写入结构（可溯源）**
```json
{
  "score": 75,
  "grade": "待复核",
  "deductions": [
    {"type": "核心字段缺失", "item": "脉象", "points": 15, "reason": "pulseList 与 pulse 均为空"},
    {"type": "逻辑冲突", "item": "证候-方剂", "points": 10, "reason": "风寒感冒 不匹配 银翘散"}
  ],
  "logicConflicts": ["证候-方剂不匹配：风寒感冒 × 银翘散"],
  "serious": false,
  "checkedAt": "2026-09-17 10:00:00"
}
```

**前端重算入口**

| 项 | 明细 |
|----|------|
| 位置 | `Governance.vue` 治理状态行右侧「**质控评分重算**」按钮（仅管理员可见） |
| 交互 | 点击 → confirm（"将按质控规则对全库重算评分与分级，覆盖现有分数，确认？"）→ loading → 提示新分布 → 刷新治理状态行 + 看板 |

**与现有链路联动**

**验收标准**：batch 后分级分布合理（非 85/12/3 随机）；抽查 `qc_results` 扣分明细与 score 一致；border 例（60/90 分）路由正确。

## 8. 开发规范与协作

### 8.1 后端规范

- **分层**：`common`（config/domain/exception/interceptors/utils）+ `controller` + `domain`（dto/po/vo）+ `mapper` + `service`（接口）+ `service/impl`（实现）；
- **命名**：`I*Service` 接口 + `*ServiceImpl` 实现（`@Service`）；绑表服务 `extends IService<Po>` / `ServiceImpl<Mapper,Po>`；
- **响应**：统一 `Result{code,msg,data}`，文件流接口（导出/日志）除外；
- **异常**：业务异常由 `GlobalExceptionHandler` 统一出口（401 / 400 / 500 → Result），**Controller 禁止 try-catch 兜错**；
- **留痕**：清洗 / 导出 / 导入 / 回滚 / 复核等关键操作调用 `OperationLogger` 写 `logs/operation.log`；
- **鉴权**：JWT（`JwtInterceptor`），放行 login / register。

### 8.2 前端规范

- **主题**：中式变量 `--ink/--paper/--line/--ochre/--danger`（见 `theme.css`），不加渐变 / emoji / 骨架滚动动画；
- **组件复用**：PanelCard / StatCard / BarList / TermInput / StatsFilter→RangeFilter / StructuredDataCard（新增），优先复用不新建；
- **请求**：统一走 `utils/request`（响应拦截 + blob 下载 `utils/download`）；接口封装于 `api/*.js`；
- **渐进增强**：mock → 真接口；后端字段缺失时降级隐藏，页面不报错。

### 8.3 契约纪律

- 新增 / 变更接口：**先更新 openapi.yaml，再实现代码**；响应字段以 openapi 为准；
- 错误码查 openapi 附录B（2001 / 4001 / 1006 / 2003 等）；前置校验统一 `IllegalArgumentException` → HTTP 400。

### 8.4 git 工作流

- 每线独立 commit、可独立回滚；commit 格式 `feat|fix|docs|refactor(scope): 描述`；
- 前端先行：本线任务前端 + mock 提交审核通过后，方可做该任务后端；
- **分支模型**：仓库维护 4 个长期分支——`main`（基线 / 合入目标）+ `XXJ` / `YC` / `ZRC`（三个成员各自的开发分支），全部使用、不删除、不过期；任务在各自分支开发，审核通过后合入 main；分支定期同步 main，避免长期分叉。

| 后端落地 | 功能主导成员 | 契约以 openapi 为准 |
| 验证 | 主导成员 + 测试成员 | `mvn test` / `npm run build` / 手工场景 |

### 8.7 并发防护约定

- **原则**：单实例部署，不使用分布式锁（Redisson）；采用「幂等 + 轻量任务互斥」；
- **任务互斥**：全库写操作（质控重算 batch / 数据清洗 clean）执行前用 Redis `SETNX tcm:task:{type} NX EX 300`（复用已有 RedisTemplate `setIfAbsent(key, value, Duration)`）抢占，占用中返回"任务进行中"；成功后 `DEL`；
- **幂等**：batch / clean 重复调用结果一致（批量前清理 pending review_tasks、跳过后台 invalid，见 2.5）；
- **词典文件**：导入 / 回滚 / 备份方法加 JVM 锁（synchronized），避免并发覆盖词典 JSON 与 ES 索引重建冲突；
- **扩展预留**：若未来扩展多实例部署，可将 SETNX 互斥升级为 Redisson 分布式锁（注明适用边界后再引依赖）。

### 8.8 角色鉴权约定

| 角色 | 菜单 | 接口权限 |
|------|------|---------|
| 管理员 | 8 项全量（首页/病历/结构化解析/质控校验/复核/清洗导出/词典/审计） | 全部（含治理/词典/质控/导出 等管理操作） |
| 审核员 | 首页看板 + 人工复核 | 登录、看板统计、复核（批D） |

- **机制**：`@RequireRole("管理员")` 标注管理接口；`RoleInterceptor` 读 request `currentRole` 校验，未过 → HTTP 403 + Result；前端路由 `meta.roles` + 守卫，`MainLayout` 按登录返回 menus 渲染；
- **演示口径**：菜单可全量展示（截图=管理员视角），但后端强制拦截越权——审核员直输管理 URL 必须 403；
- **新增接口默认**：写操作默认"仅管理员"，只读接口默认"登录即可"，复核专接口默认"双角色"。
