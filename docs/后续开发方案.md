### 2.5 线B-4：AI质控评分（分数真实化）

**后端算法**
| 模块 | 设计 |
|------|------|
| `common/utils/QcScorer.java` | **判空规则**：核心字段按 structured_data 非空判断<br>structured 为空再回退查原始列（pulse/tongue/pattern/prescription）<br>两者皆空才判缺失 |
| 三层扣分 | ① 核心缺失各 -15（6项）<br>② 逻辑冲突各 -10（证候-治法/方剂/中药）<br>③ 格式（age 非数字/性别非男女）+ 重复（文本MD5冲突）+ 症状为空 各 -5 |
| 严重判定 | 核心缺失 ≥3 / 证候-治法与证候-方剂同时冲突 / 无法解析 → 直接 invalid；`score = max(0)` |
| 分级路由 | ≥90 无冲突 → 合格<br>60≤score<90 或逻辑冲突 → 待复核<br><60 或严重 → 无效 |
| `common/utils/LogicChecker.java` | 3条证候映射：<br>· 风寒 → 辛温解表 → 麻黄汤/桂枝汤<br>· 风热 → 辛凉解表 → 银翘散/桑菊饮<br>· 暑湿 → 清暑祛湿 → 新加香薷饮<br>+ 2条舌脉规则（舌红×脉沉迟、舌淡×脉数）<br>**未覆盖证候不判冲突（不误杀）** |

**接口**
| 接口 | 说明 |
|------|------|
| `POST /api/qc/score` | 单条评分，返回 `ScoreResultVO`（score/grade/deductions/logicConflicts） |
| `POST /api/qc/score/batch` | 全库重算（事务 + 逐条幂等），返回分布统计（合格x/待复核x/无效x） |

**预检单落库**
- `records.qc_results` 写入 `{score, grade, deductions:[{type,item,points,reason}], logicConflicts:[...], serious, checkedAt}` —— **可溯源**
- 待复核病历自动生成 `review_tasks`（pending，deadline=+7工作日）到**数据层**（UI 属线C待定）

**前端重算入口**
| 项 | 明细 |
|----|------|
| 位置 | `Governance.vue` 治理状态行右侧「**质控评分重算**」按钮（**仅管理员**可见） |
| 交互 | 点击 → confirm（"将按质控规则对全库重算评分与分级，覆盖现有分数，确认？"）→ loading → 成功提示新分布 → 自动刷新治理状态行 + 看板数据 |
| 失败态 | 401/500 统一错误提示；接口未开通时按钮置灰 tooltip"后端预留" |
| mock 形态 | 审核阶段按钮先用假分布演示（真实接口由后端提供） |

**与现有链路联动**
- 重算后看板 overview 数字自然正确；导出/预览只导"真实合格"（范围变化属预期）；`governed` 保持现状不重置
- 批量前清理旧 review_tasks(pending) 防重复；性能：500 条内存循环 + 词典查询 <1s；重复调用结果一致
