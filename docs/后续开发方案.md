# 中医电子病历质控与标准化系统 - 后续开发方案

> 版本：v1.0
> 日期：2026-09-17
> 定位：**后续待实施工作的唯一规划入口**（不写入交付报告；交付报告仅记录已完成内容）
> 主线：**「可解释AI质控 + 人机协同评估」**

---

## 1. 背景与现状

### 1.1 组会反馈（老师提出）
1. **预览滚动体验差**：清洗与导出页"预览数据集"弹窗内，点击后表格只显示2条，剩余8条需上下拖动滚动条才能看到
2. **JSON展示体验差**：单条病历详情弹窗底部，结构化数据（structuredData）以 JSON 格式展示，用户体验不好

### 1.2 系统现状
- **质控评分假数据**：`score`/`grade`/`status` 由 seed 脚本随机生成（85%/12%/3%），与病历内容无关；`calculateScore` 算法尚未实现
- **AI应用缺失**：归一无溯源、无质控解读、无智能辅助入口，科研价值薄弱
- **线C未做**：人工复核工作台、一致性评估（Cohen's Kappa）等科研模块未启动

### 1.3 目标
修复组会反馈 + 落地 AI 应用层（让 AI 真正作用于业务）+ 预留科研评估框架。

#### B4 AI质控评分落地（分数真实化）

**后端算法**：
| 模块 | 设计 |
|------|------|
| `common/utils/QcScorer.java` | **判空规则**：核心字段按 `structured_data` 非空判断，若 structured 为空再回退查原始列（pulse/tongue/pattern/prescription），两者皆空才判缺失 |
| 三层扣分 | ①核心缺失各 -15（6项）②逻辑冲突各 -10（证候-治法/方剂/中药）③格式（age 非数字/性别非男女）+ 重复（文本MD5冲突）+ 症状为空 各 -5 |
| 严重判定 | 核心缺失 ≥3 / 证候-治法与证候-方剂同时冲突 / 无法解析 → 直接 invalid；`score = max(0)` |
| 分级路由 | ≥90 无冲突 → 合格；60≤score<90 或逻辑冲突 → 待复核；<60 或严重 → 无效 |
| `common/utils/LogicChecker.java` | 文档9.3规则：3条证候映射（风寒→辛温解表→麻黄汤/桂枝汤；风热→辛凉解表→银翘散/桑菊饮；暑湿→清暑祛湿→新加香薷饮）+ 2条舌脉规则（舌红×脉沉迟、舌淡×脉数）；**未覆盖证候不判冲突（不误杀）** |

**接口**：
| 接口 | 说明 |
|------|------|
| `POST /api/qc/score` | 单条评分，返回 `ScoreResultVO`（score/grade/deductions/logicConflicts） |
| `POST /api/qc/score/batch` | 全库重算（事务 + 逐条幂等），返回分布统计（合格x/待复核x/无效x） |

**预检单落库**：
- `records.qc_results` 写入 `{score, grade, deductions:[{type,item,points,reason}], logicConflicts:[...], serious, checkedAt}` —— **可溯源**
- 待复核病历自动生成 `review_tasks`（pending，deadline=+7工作日）到**数据层**（UI 属线C待定）

**前端重算入口**：
| 项 | 明细 |
|----|------|
| 位置 | `Governance.vue` 治理状态行右侧「**质控评分重算**」按钮（**仅管理员**可见） |
| 交互 | 点击 → confirm（"将按质控规则对全库重算评分与分级，覆盖现有分数，确认？"）→ loading → 成功提示新分布 → 自动刷新治理状态行 + 看板数据 |
| 失败态 | 401/500 统一错误提示；接口未开通时按钮置灰 tooltip"后端预留" |
| mock 形态 | 审核阶段按钮先用假分布演示（真实接口由后端提供） |

**与现有链路联动**：
- 重算后看板 overview 数字自然正确；导出/预览只导"真实合格"（范围变化属预期）；`governed` 保持现状不重置；批量前清理旧 review_tasks(pending) 防重复
- 性能：500 条内存循环 + 词典查询，预计 <1s；重复调用结果一致

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 预览表格 520px 后页面较长 | 小窗口仍需滚动 | 保持；表格位于页面下半部，不影响核心操作 |
| 重算后合格数量剧变（可能从441大跌） | 答辩数字变化 | 属预期；文档/答辩口径统一"评分规则真实化" |
| checkLogic 规则仅3条（覆盖率窄） | 部分冲突不被检出 | 标注"固定内置规则，未覆盖证候不判冲突（不误杀）"，符合文档"写死不支持自编辑" |
| 前端 mock 与后端真数据不一致 | 审核所见与上线不符 | 阶段设计"渐进增强"：无接口/字段时自动降级隐藏 |
| 归一重跑清洗耗时 | 500条预计<1s | 可忽略 |
| 悬浮窗 z-index 遮挡 | 干扰操作 | 置顶但不遮菜单；收起后不挡交互 |
| 线C 需 review_tasks 扩展列 | ALTER TABLE | 线C 实施时执行；database-init.sql 同步 |
