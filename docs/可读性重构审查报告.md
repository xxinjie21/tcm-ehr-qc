## 三、命名规范

- **Controller 路由风格不统一（实测）** —— 类级 `@RequestMapping` 前缀 5 个：`Ai` / `Auth` / `Dictionary` / `Llm` / `Stats`；方法级写全路径 6 个：`Governance` / `Log` / `Nlp` / `Qc` / `Record` / `Review`（例：`GovernanceController.java:49` `@PostMapping("/api/governance/normalize")`）。建议统一为类级前缀。风险低（URL 不变、不触契约）。
- **分页参数两个名字** —— `LogController.java:48` 用 `size`，`ReviewController.java:43` 用 `pageSize`。openapi 首部自述「统一 page + pageSize」，但 `/api/logs` 定义的是 `size`。统一为 `pageSize` **必须先改 openapi.yaml**（**BOM + LF** 文件，需按字节补丁）。风险中高（触契约）。
  - 2026-09-28 更正：本条原写「BOM + **CRLF**」有误 —— 实测全文件 **0 个 CR 字节**、3474 个行尾全为裸 LF（`.gitattributes` 有 `* text=auto eol=lf`）。按 CRLF 处理会让整份文件 diff 炸开。
- **前端「重置」四个名字** —— `handleReset`(Records) / `resetQuery`(NlpExtract) / `resetFilters`(Qc) / `resetCols`(Governance)。建议统一为 `resetFilters`。风险低。
- **`fieldOf` 与 `fieldsOf` 同形近义** —— `Review.vue:239` 的 `fieldOf` 是「取字段值」，`Records.vue:292` 的 `fieldsOf` 是「取分区定义」。建议后者改名 `groupFields`。风险低。
- **缩写变量** —— 后端 `Object o`（`AiServiceImpl.java:598`、`GovernanceServiceImpl.java:425`）、`Map<?,?> m`、`OperationLog l`（`AiServiceImpl.java:402`）；前端 `sd`（`Review.vue:375/390`）、`sr`（`Review.vue:472`）、`ov`/`ex`/`g`（`Dashboard.vue:251/260`）。建议改为完整词。风险低。
- **`api/nlp.js:14` 的 `getNlpBatch` 实为单任务进度** —— 与 `listNlpBatch()` 易混，建议改 `getNlpBatchProgress`。风险低。
- **模块与接口域错位** —— `api/governance.js:13/17` 的路径是 `/export/*`；`api/review.js:9` 的路径是 `/records/{id}/review`。建议归位或加注说明。风险低。
- **`stores/ai.js` 的 `useAiStore` 实存清洗上下文** —— 内部是 activeRecord / normByLevel / stats，与 AI 无关。建议改名。风险中（引用面广）。
- **日期格式化多套口径** —— `fmtDateTime`（到秒）、`Review.vue:275` 的 `fmt`（到分）、`fieldOf` 内联（到秒）、`Governance.vue:342` 的 formatter（到日）、`AuditLog.vue:51` 内联（到秒）。建议收敛到 `utils/format.js` 并统一命名。风险低。

## 五、结构层次

- **`GovernanceController.java:97-108` 手工拼 400 错误体** —— 注入 `ObjectMapper` 手工拼 `400 + code=2001` 的 JSON，绕过 `GlobalExceptionHandler`。建议下沉为业务异常由 handler 统一转。风险中（须确保仍返回 400 / 2001，属契约行为）。
- **数据访问风格两套** —— `AiServiceImpl` / `LogServiceImpl` / `NlpBatchServiceImpl` 等直接注入 Mapper；另 6 个 `extends ServiceImpl` 用 `baseMapper`，且 `RecordMapper` 被两套同时使用。建议统一。风险低。
- **`NlpExtract.vue:876` 的 `rerun = () => submitBatch()`** —— 纯转发，模板可直接绑 `submitBatch`。风险低。
- **`utils/request.js` 略重** —— 兼含 axios 实例、两个拦截器、`apiErrorMessage`，且依赖 router 与 store。
- **`api/*.js` 全是逐字转发薄封装** —— 判断是**有意分层**（集中 baseURL / timeout / responseType 与参数形状），**建议保留**，见第九节。

- **小函数注释体例分裂** —— `handleSizeChange` 在 `AuditLog.vue:166`、`Records.vue:331` 用 `/** … */`，而在 `Qc.vue:631`、`NlpExtract.vue:421`、`Review.vue:304` 用 `//`。

## 七、Python（`python-nlp/`）

整体注释质量最高（文件级 docstring + 函数级 docstring + `// 1.` 式步骤标号三层齐全）。仅 4 处小问题：

- **`_load_model()` 的 `import torch` 未被使用** —— 函数内只用 `transformers`。注意：它可能是「提前验证 torch 可用」的防御性导入（torch 缺失时走到 `except` 降级），删除前需确认这一意图。
- **`except Exception as e:` 中 `e` 未使用** —— `logger.exception` 自带异常信息，`as e` 可去掉。
- **`_rules()` 的 `dict.fromkeys(RULE_CAUSE_WORDS)` 去重冗余** —— `RULE_CAUSE_WORDS` 本身无重复项，注释称「去重并保序」与实际不符。
- **`_flush()` 参数无类型标注** —— 同文件其余函数均有标注。

## 九、明确不做

1. **`api/*.js` 的薄封装层** —— 它集中了 baseURL / timeout / responseType 与参数形状；删掉会让每个调用点各写一份 axios 参数。属有意分层，保留。
2. **`str(Object)` 三份直接合并** —— 三者语义不同（不 trim / trim 后空转 null / null 转空串），合并即改行为。正确做法是按语义改名。
3. **任何与 `docs/开发指南与待办.md`「六、待办」重叠的条目** —— 那些已单列，本报告不重复：TDZ 8 处、各类静默截断、只写不读字段、全局锁与 TTL、前端校验与后端不一致、同一数据传两遍、`cancel()` 状态语义等。
4. **为一致性改契约字段名**（除 `/api/logs` 的 `size` 单列评估）—— 项目既定原则是「能不动就不动」。
