## 〇、协作铁律（最高优先级）

- 未经用户明确指示，不得修改任何代码、配置或文档。
- 审查 / 扫描 / 分析 / 核实 / 出计划一律只读；发现问题**如实汇报，不擅自修复**。
- 只改被点名的范围，不顺手扩大；一次只做当前要求的事，做完停下等下一步指示。
- 需要判断时先问，不替用户做决定。
- 例外：用户显式授权的当次任务即为授权范围。

| 测试数据 | `docs/电子病历精简脱敏数据_500行.xlsx`；词典 `java-backend/src/main/resources/dictionaries/*.json`（**基础层首次播种 + 每次启动按文件重播**，改完重启即生效；运行时真源是 `dictionary_terms` 表） |
| 规模 | 真实 ≥3 万条；批量上限 `qc.batch.max-records=40000` |
| 契约源 | `docs/中医电子病历智能结构化与数据质量控制系统-openapi.yaml`（唯一基准，权限五档） |

**三条铁定口径**

1. ES 召回、Java 判定。归一只认 ES，无内存兜底；ES 不可用 → 503 + code=1010，绝不静默判「未收录」。
2. 判定地基是规则引擎。评分 / 分级 / 归一不依赖 LLM；LLM 只做叙述加工，失败即降级。
3. 实体目录单一来源 `EntityTypes.all()`（当前 8 类、均有词典，「治法」已移除）；归一范围与「未归一扣分」范围分别由 `QcRuleSet.normalization.elementTypes` / `standardization.elementTypes` 决定（出厂默认计分 5 类）。

**配置**：`spring.ai.model.*` 六项置 `none`（否则缺 api-key 时启动失败）· 路径类配置含绝对路径，换机需改 · 开关 `nlp.enabled`（true，开前先起 :8001）/ `llm.enabled`（false，仅启动基线）· `llm.api-key` 不落盘 · 配置注释只写「是什么 / 默认值 / 改它的前提与后果」。

> 权限口径以 `角色与权限矩阵.md` 为准。

## 二、注释规范

注释解释「为什么」，代码自解释「是什么」。一律纯文本。

**禁止**在注释里写 `<p>` `<b>` `<ul>` `<li>` `<br>` `{@code}`。**唯一例外** `{@link Xxx}`（IDE 可跳转）。

| 想表达 | 不要写 | 改写 |
|---|---|---|
| 分段 | `<p>…</p>` | 空行分隔 |
| 强调 | `<b>关键</b>` | 独立成句，或 `注意：` / `⚠️` 开头 |
| 行内标识符 | `{@code groupId}` | 直接写 `groupId` |
| 列举 | `<ul><li>` | 每行 `- ` 起头 |

**后端骨架**

```java
/**
 * 病历公共过滤：数据域（行级权限）→ 用户筛选，顺序固定、取交集。
 *
 * 所有病历读取统一走本工具，禁止在业务方法中手写 where。
 *
 * ⚠️ fail-closed 是最关键的一行：groupId 为空时必须返回空集，不能不加条件 —— 那等于看到全库。
 */
public final class RecordFilter {

    /** 每处理多少条落一次进度：每条都写会把库压垮 */
    private static final int PROGRESS_EVERY = 25;

    /**
     * 构建查询条件：先数据域、后用户筛选。
     *
     * 【权限：登录即可】
     *
     * @param groupId 当前主组，为空即无可见数据
     * @return 已含数据域与排序键的查询条件
     */
    public static QueryWrapper<Record> build(String groupId, SearchDTO dto) {
        // 1. 数据域（行级权限）——必须先于用户筛选
        operatorScope(wrapper, groupId);
        // 2. 用户筛选（与数据域取交集）
        ...
    }
}
```

- 类级：概述 → 空行 → 动机与后果 → 危险点单独一段，以 `⚠️` 开头。方法级：概述 → 空行 → 行为与边界 → `@param` / `@return` / `@throws`；Controller 方法首段带权限标注（§九）。字段 / 常量：一行 `/** ... */` 说明取值口径。
- 函数体内多阶段用 `// 1. // 2. // 3.` 编号，非显然的决策写「为什么」。分节分隔线：后端 `// ---------------- 中文分节名`（右对齐）· 前端 `// ===== 中文分节名 =====`。
- 前端：仅「唯一副本」模块写文件头块注释（如 `utils/structured.js`）；模板注释用 `<!-- -->` 讲结构决策。Python：模块 docstring 写用途 + 运行方式 + 模型来源，常量 / 正则用 `#` 说明口径与取舍。
- 措辞纪律：中文正文禁「治理」字眼，状态词统一「待清洗／已清洗」（英文标识 `Governance*` 不改）· 面向业务用户禁泄漏实现细节（正则 / 英文 key / 目录名 / 字段名）· 注释必须与实现一致。
- 注释一律纯文本：改到哪个文件就把该文件注释一并改纯文本，不做全库重排。Java 与前端部分注释仍含 `<p>` / `<b>` / `<ul>` / `<li>`，迁移只动注释，改完 `git diff --stat` 确认。

## 三、可读性

**命名**

| 对象 | 规则 | 示例 |
|---|---|---|
| 服务接口 / 实现 | `I*Service` / `*ServiceImpl` | `IQcService` / `QcServiceImpl` |
| 请求 / 响应 | `*DTO` / `*VO` | `QcBatchDTO` / `QcTaskVO` |
| 实体 / 工具 | 表名单数驼峰 / 名词全静态 | `Record` / `RecordFilter` |
| 前端接口 / 组件 | 动词短语 / PascalCase 文件名 | `recomputeQc` / `PanelCard.vue` |
| DB 列 | 下划线 | `visit_time` |

- 名字说清「是什么」，禁 `data1` / `temp` / `flag` / 单字母（循环下标除外）；布尔量用 `is*` / `has*` / `can*`；常量全大写下划线并注释口径。

**文件组织**

- 后端：`common`（config / domain / exception / interceptors / utils）+ `controller` + `domain`（dto / po / vo）+ `mapper` + `service`（+ `impl`）。一个文件一个主类，辅助类可 `public static class` 内嵌；同类多 DTO 合并进 `*DTOs.java`。
- 前端：`api/*.js`（一模块一文件）+ `stores/` + `components/`（+ `cells/`）+ `views/` + `utils/` + `styles/theme.css`（主题令牌唯一权威）。

**函数职责单一**

- 一个方法只做一件事，方法名能概括全部行为；超出「一眼看完」就抽私有方法。
- 参数 ≤4（更多聚成 DTO）；嵌套 ≤3 层，用早返回替代深层 if。
- 不用 boolean 参数控制分支（`importRecords(files, autoExtract)` 属例外，语义明确）。

**禁魔法值 · 单一来源**

- 固定常量抽离具名并注释，禁止业务代码里散落字面量。
- 同一事实只有一处权威：实体类型 `EntityTypes` · 质控规则 `QcRuleSet` · 性别白名单 `QcRuleSet.GENDER_VALUES` · 展示措辞 `utils/structured.js` · 主题色 `theme.css`。第二处只能引用，不得复制。

## 四、健壮性

**异常处理**

- 业务异常统一由 `GlobalExceptionHandler` 出口；Controller 禁 try-catch 兜错。
- 校验失败抛 `IllegalArgumentException` → 400 · 资源不存在 `ResourceNotFoundException` → 404 · 越权 `ForbiddenException` → 403 · 需自定义码与状态用 `BusinessException(code, message, status)`。
- HTTP 状态表达「哪一类失败」，`code` 表达「具体原因」；参数类异常一律 400，不落兜底 500。兜底分支生成 traceId，异常原文只进日志。
- ES 客户端异常是 unchecked（`ElasticsearchException`），必须 `catch (Exception)`，不能只 catch `IOException`。
- 前端文案走 `utils/request.js` 的 `apiErrorMessage(e, fallback)`；拦截器 reject 的是 axios 原始 error，禁在 catch 里直接写 `e?.message`。

**边界条件**

- 空值 / 空串 / 空集合都显式判断；`Number(null)` 与 `Number('')` 都是 0，展示前必须挡（见 `pct()`）。
- 时间区间必须上下界同时存在才生效，只给一端按「未给」处理。
- 分页强制上限，超限 400；批处理单次上限 `qc.batch.max-records`，失败清单只存前 500 + 截断标记。
- 写库前评估 JSON 列体积，防撑爆。
- fail-closed：范围 / 权限条件缺失必须生成「返回空集」的查询，绝不「不加条件 = 看全库」。
- 空结果先问：是判过没有，还是根本没判；不得把「没做」说成「没问题」。

**输入校验**

- DTO 用 jakarta 注解（`@Min` / `@Max` / `@Size` / `@Pattern`），Controller 参数加 `@Valid`。
- 校验口径与 DB 列宽、质控规则对齐；白名单收敛单一来源；前后端一致（前端补 `maxlength`）。
- 上传校验扩展名、大小（单文件 / 请求 50MB）、数量（≤20）、必需列。

## 五、持久性

**存储可靠**

- 全新库结构只由根目录 `database-init.sql` 建立（单文件执行即可，含表 / 索引 / 种子数据）；存量库增量走 Flyway `java-backend/src/main/resources/db/migration/V{n}__*.sql`，应用启动时自动执行（baseline v1），新库上均为幂等空操作。**改结构必须同时改这两处**。
- 落盘：质控规则 `qc_rules` 表（每组织一行；字段级深合并，非法回默认并告警）· 词典词条 `dictionary_terms` 表（基础层 `org_id=''` 由 `resources/dictionaries/*.json` 在每次启动按内容版本重播，组织层叠加）+ 索引版本 `dictionary_versions` · LLM 配置只存内存，`api-key` 不落盘。

**事务完整性**

- 写操作标 `@Transactional`，边界在 Service 实现层（`TransactionAnnotationTest` 守护）。
- 批量写分块（`DELETE_CHUNK=500`），先删从表（`review_tasks`）再删主表（`records`）；跨表写同一事务，失败整体回滚。
- 单实例下不引入行锁 / 乐观锁 / 分布式锁，一致性由 SQL 语义（唯一键 + 事务）与幂等兜底。多实例场景的 Redisson 分布式锁由 `RedissonConfig` 装配，用于词典索引重建等跨实例互斥（见 `DataInitializationListener`）；锁只降冲突概率、不承担正确性。

**幂等与防重**

- 全库写操作（重算 / 清洗）防重查表：`qc_task` 是否已有 QUEUED / RUNNING，不用 Redis 单键锁。
- `review_tasks` 幂等 upsert；前端按钮 disabled + loading 先拦一道，后端兜底。
- 词典导入 / 回滚 / 备份与启动重播共用 Redisson 分布式锁（`DistLock.dictRebuildLock`，按 `类型+组织` 粒度），防多实例「先删后插」交错破坏索引。

**内存态与重启**

- 进程内状态必须标注：`NlpBatchServiceImpl` 队列 / 取消位 · `LlmConfigStore` · `QcRuleStore` · 导入进度 Map。
- 重启把 `RUNNING` / `QUEUED` 一律标 `INTERRUPTED`，不重新入队。
- worker 线程拿不到 `RequestContextHolder`，`currentRole()` 返回字符串 `"unknown"`（不是 null）：提交时把角色写进 `qc_task.role`，worker 用捕获值重建过滤器，审计日志显式回填操作人。

## 六、完整性

**业务覆盖**

- 每层只做自己的事：Controller 只编排 · Service 承载业务 · Mapper 只访问数据。
- 所有分支都要有处理与提示，不留「点了没反应」。
- 关键路径必须可测：评分 / 归一 / 鉴权要有单测。
- 同一口径多处消费时同时改或统一措辞。典型：核心字段缺失，`QcRuleSet.completeness.elements` 是 6 要素两档扣分，`AiServiceImpl.coreMissing` 是 5 项只算真缺失。

**数据一致性**

- 三方一致：openapi ↔ Controller ↔ 前端签名（路径 / 方法 / 参数 / 权限）逐一对照。
- 同一事实一个权威：阈值 / 分级 / 文案不得前后端各存一份。
- 跨页对得上：看板、分级、导出、日志的数字。
- 排序键 = 列表实际展示的那一列（`RecordFilter` 的 `visit_time`，为 null 排最后）。`visit_time` 有四个下游（列表列 / 月份趋势 / 按时间筛选 / `textHash` 的 21 字段之一），全空会同时退化四处。

**空态与截断**

- 留着的列必须有值；空态必须解释「为什么空、怎么才会有内容」。
- 任何静默截断都要在界面明示：扣分明细前 20 / 趋势 12 个月 / 失败样本前 500 / 任务列表 50。
- 裸数字不许直出，必须带标签 + 两位百分比。

- 提到 `common/utils` 的必须无状态；有状态的服务放 `service`。

## 八、架构（低耦合 · 高内聚）

**依赖方向**（单向向下，禁反向与跨层）

```
controller → service(impl) → mapper → DB
     ↘            ↘
      domain(dto/po/vo)   common(config/exception/utils/interceptors)
```

- `common` 不依赖 `controller` / `service` / `mapper`；`controller` 不直接调 `mapper`；`domain` 是纯数据载体。
- 前端 `view → store / api → utils`，组件不直接发请求。

**依赖管理**

- 后端构造器注入（`@RequiredArgsConstructor` + `final`），禁字段注入。
- 跨模块只经接口（`I*Service`），不引用实现类。例外：`QcBatchServiceImpl` 复用 `QcServiceImpl.processOne`。
- 前端 `api/*.js` 是唯一出口，组件内禁直接 `axios`。
- 新增第三方依赖前先确认既有能力是否已覆盖。
- 禁止在业务代码里内联全限定类名（FQCN）。规范做法是在文件顶层 import，正文只用类名：
  - ❌ `com.tcm.ehr.common.cache.StatsCacheInvalidator.invalidate();`
  - ✅ `import com.tcm.ehr.common.cache.StatsCacheInvalidator;` → 正文写 `StatsCacheInvalidator.invalidate();`

**模块边界**

- 按业务域划分服务：病历 / 结构化解析 / 质控 / 复核 / 词典 / 清洗导出 / 统计 / 日志 / 课题组 / AI。
- 模块间通过 `Result` + DTO / VO 通信，不共享可变状态。
- 数据域统一走 `RecordFilter`，顺序固化：先数据域、后用户筛选，取交集；`selectById` 类路径用 `RecordFilter.canAccess(record)` 查后校验。
- 契约先行：先改 openapi.yaml，再写代码。

## 九、契约与 git

- openapi.yaml 是唯一接口基准，新增 / 变更接口先更新它。
- 每个接口 `description` 首部必须带权限标注，五档：`公开` / `登录即可` / `本人` / `管理员 / 所有者 / 授权成员` / `仅管理员`。
- 错误码查 openapi 附录 B；前置校验统一 `IllegalArgumentException` → 400。
- 鉴权：`@RequireRole` + `RoleInterceptor`（未过 403）；新增接口默认写操作「仅管理员」、只读「登录即可」、组织级配置写「管理员 / 所有者 / 授权成员」、个人配置「本人」。数据域：管理员看全部（受 `auth.admin-can-view-data` 开关控制），其余身份只看当前组织。
- 前端 `router` 的 `meta.roles` + 守卫，菜单按角色动态渲染；鉴权不依赖 localStorage。
- commit 格式 `feat|fix|docs|refactor|chore(scope): 描述`；分支 `main` + `XXJ` / `YC` / `ZRC`，MR → 评审 + 验收 → merge。
- 合 main 前 `grep -rn "graph-preview|静态假数据" src/`，禁预览桩合入。

## 十、技术决策与已知问题

> 本章由二十余份已收口的过程方案、审查报告提炼而成；原文件已从仓库移除，
> 以下为继续开发必须保留的结论与当前真实缺口。数字均为实测，勿凭印象改口径。

### 10.1 已定案（不要反复讨论）

- **归一只认 ES 索引**：无内存兜底，ES 不可用 → 503 + `code=1010`，绝不静默判「未收录」。
- **LLM 只做叙述加工**（质控解读 / 复核预检 / 术语补词），不参与评分、分级、归一判定，失败即降级。
  **不做** AI 编排 / 工具调用：失败模式会从「答不上来」变成「看起来对的错数字」。
- **LLM 配置只存内存**（`LlmConfigStore`），不写回 yml；`api-key` 不落盘。
- **权限**：openapi 每个接口 `description` 首部必须带【权限：…】；后端 `@RequireRole` + `RoleInterceptor`，
  前端 `meta.roles` + 守卫；数据域统一走 `RecordFilter`（先数据域、后用户筛选，取交集）。
  词典写权限三档：提案提交＝登录即可 / 审核合并＝所有者 / 基线导入＝仅管理员。
- 接口前缀不加 `/api/v1`；响应统一 `Result{code,msg,data}`；Controller 禁 try-catch 兜错。
- **2026-10-06 起计划内剩余项终止、不再执行**；其后提交均为质量整改，不是新功能。
- 「AI 助手问答」整条竖切已删除（Flyway V6 删 `user_llm_config.chat_enabled`）；
  `database-init.sql` 不含该列是终态，不是遗漏。
- 不做批量推理优化：CPU 上实测 `torch=4 线程 / 并发=8` 已最优，批量推理为 0.36~0.60x 负优化。
  再提速只能上 ONNX。

### 10.2 NLP 与词表（改动前必读）

- `python-nlp/nlp_rules.py` **两条正则不许收窄**：
  1. `RULE_TONGUE_MORPH` 的「边有」不许改成「边有齿痕」——会丢「边有瘀斑」，
     而演示数据只写「边有齿痕」，损失在那份数据上看不出来，属隐蔽回归；
  2. `RULE_PULSE_POSITION` 不许加脉质字白名单——「左尺无力 / 左关尤甚」后缀不在白名单内，
     实测脉象 144→120 条次（-16.7%）。
- **词表 / 规则不许凭空扩**。加词前先 grep `java-backend/src/main/resources/dictionaries/`：
  - 该词已是某条目的 `standardTerm` / `aliases` → 属于那一类，加进来是跨类重复计数；
  - 8 本词典全无落点 → 凭空扩表，不加；
  - 只有「词典里有归一目标、但当前抽不到」才值得加。
- `MODEL_DIR` 默认值 `"model"` 是**相对路径**；工作目录不在 `python-nlp/` 时会静默降级为
  `modelAvailable=false`，只剩规则兜底。
- `python-nlp/main.py`（HTTP 层）与 `schemas.py` / `nlp_rules.py` / `nlp_model.py` 已按依赖方向拆分；
  `nlp_model` 的 `_model` 启动时才赋值，禁止 `from nlp_model import _model`（只会拿到 None 快照）。

### 10.3 数据口径

- 演示数据按「临床模板」看：500 行仅约 120 个「主诉 + 辨证结论」组合 / 10 类疾病。
- `visit_time` 全空会**同时退化四处**：列表接诊时间列 / 就诊月份趋势 / 按接诊时间筛选 /
  `RecordUtil.textHash` 的 21 字段（哈希不同 → 跨批去重失效）。`text_hash` 已落库并以
  `(org_id, text_hash)` 唯一。
- 接诊时间（`visit_time`，Java 侧过滤）与导入时间（`create_time`，下推 SQL）是两个独立维度，
  可同时生效取交集；导入区间排除量不进 `excluded`。
- 两套「核心字段缺失」口径：质控 6 要素两档 / `AiServiceImpl.coreMissing` 5 项，
  **改一处必须同时改另一处**。
- 实体目录以 `EntityTypes.all()` 为准（当前 **8 类、均有词典**，「治法」已移除）；
  归一范围与「未归一扣分」范围分别由 `QcRuleSet.normalization.elementTypes` /
  `standardization.elementTypes` 决定（出厂默认计分 5 类）。
- 裸数字不许直出，必须带标签 + 两位百分比；实心标签说明「怎么来的」，描边标签说明「归一准不准」。
- **「没做」不许说成「没问题」**：看到空结果先问是判过没有，还是根本没判。
