### 0.4 本机工具陷阱

- 临时脚本写 `.workbuddy-ai/tmp/`，**不要写 `/tmp`**（Git Bash 与原生 Python 的 `/tmp` 不是同一个）。
- 删文件用 Python `os.remove` 逐文件，**绝不用 `git rm`**（本沙箱会连父目录一起删）。
- **同一文件不要在同一条消息里发多个 Edit**（并发读改写会静默丢编辑）。要么串行，要么写一次性 patch 脚本（须 `newline=""` 读写以保住 CRLF/BOM）。
- `openapi.yaml` 是 **BOM + CRLF**（实测：有 BOM、3540 个 CRLF、0 个裸 LF）。改它必须按字节补丁，整文件重写会产生全文件 diff。
- 打接口做验收用受管 Python + `urllib`（`ProxyHandler({})` 绕代理）；`curl -o` 在本机 Git Bash 退出码 23。
- 表格按显示宽度补空格（`unicodedata.east_asian_width`，W/F 记 2），表格前空一行。既有文档最宽 124~219 显示宽度，**超过 220 就该把散文单元格的表改成列表**。
- 前端布局类结论**一律实测**，不要读 CSS 推算。量「有没有内部滚动条」必须量 `.el-table__body-wrapper .el-scrollbar__wrap` 的 `scrollHeight - clientHeight`。

### 0.5 会被误当成「只读」的写操作

- **起后端不是只读**：`DataInitializationListener` 启动时会写 Redis 键 `tcm:startup:ping`，并对 5 类词典各调一次 `rebuild()`（delete + create ES 索引）。`rebuild` 的 delete→create 窗口内归一接口回 503（`code=1010`）—— 这正是 B3-2 要修的东西，验它的时候要意识到你也在制造它。
- **`logs/operation.log` 是交付物**，测后必须还原。登录、查图谱不写日志；重算 / 清洗才写。
- 灌库与查询必须加 `--default-character-set=utf8mb4`，否则中文列乱码、`GROUP BY` 出假重复。
- 改 yml 注释要能证明「没动配置值」：把新旧两版的注释全部剥掉再 diff，配置行应逐字节相同。
- NLP 服务启动必须在 `python-nlp/` 目录下执行 —— `MODEL_DIR="model"` 是相对路径，在别处启动会**静默**加载失败（服务照常起、`/health` 照常 ok，只是 `modelAvailable=false`、只剩规则兜底）。

### 2.2 逐簇说明

**簇 A 口径分裂（最高优先级）**

这是两份报告共同指向的第一问题。表现形式有四种：契约与实现不一致（G1）、文档与实现不一致（M16）、界面文案写死（H2）、AI 与质控两套判定（H1）。四种表现指向同一条规则：**凡是会在界面上出现的判定结论，口径只有一份，且由后端下发**。这一条不修，后面每加一个功能都会多一处对不上。

**簇 B 范围与数据域**

用户报告里「重跑实际是重跑全库」与代码报告里「序列化失败静默退化为全库扫描」是同一个链路的两个断点。加上导出丢 `grade`（M10）、统计绕过 `RecordFilter`（Z2），这一簇的共同修复目标是：**范围参数只允许有一个组装函数、一条传输路径，任何一环拿不到范围都必须失败而不是退化**。

按这条目标回看 `StatsServiceImpl.stats(StatsDTO)`，它有**三个**入口绕开了 `RecordFilter`：无筛选时的 `selectList(null)`（`:77`）、按 `recordIds` 时的 `selectBatchIds`（`:71`）、以及 `filterByFilters()` 的 `selectList(null)`（`:241`）。三者都要收口，只改前两个等于没改（见 B1-1）。

**簇 C 写操作原子性**

全仓库 `@Transactional` 为 0，而 `fk_review_record` 外键存在。这一簇里有三处「两个写操作之间可能失败」：先删子表再删主表（G2）、先覆盖词典文件再重建 ES 索引（G2/M4）、先置分数再改任务状态（G2）。ES 与文件系统无法随事务回滚，需要改成「临时态 校验 原子替换」的两阶段写法。

**簇 D 凭据与隐私**

JWT secret 与项目名强相关且提交进仓库，等于 `@RequireRole` 全部可绕过。`StdOutImpl` 把 SQL 与绑定参数打全量，病历正文与登录用户名整段进日志文件。脱敏则是「有函数、没字段、预览路径还漏走」。三者应一次收口。

**簇 E 导入与批处理**

`Row.getCell(-1)` 让缺列时每行都失败且报 POI 内部错误；`writeJson` 返回字符串 `"null"` 让任务退化；停机时 `finally` 把任务标成 `COMPLETED`。共同点是**边界输入与长任务的状态语义没定义**。

**簇 F 业务可见的文案**

12 条里没有一条是「功能不工作」，全部是「说法不对」。用户视角报告第四节把它归纳为四类：两个权威、按钮名与行为不符、实现细节泄漏、空态不解释。这一类改动量小、收益最直接，但**必须排在簇 A 之后**，否则口径还会再变一次。

**簇 G 前端工程一致性**

  - 验「优雅停机」那条留给能对进程发 Ctrl+C 的人：在终端里 `mvn spring-boot:run`，跑到一半按 Ctrl+C，重启后看任务状态。**别用 `taskkill /F` 或 `os.kill` 当成优雅停机**（见 `ENV-TRAPS.md`）
