# LLM 配置与使用指南

面向「要让 AI 功能真正跑起来」的使用者与部署者。涉及顶栏入口「**导入 LLM**」。

---

## 一、这个功能是干什么的

顶栏右侧的「导入 LLM」用来配置**当前登录用户自己**要用的模型通道。它是**每人一份**的：
A 配的通道和密钥不会流到 B，管理员也只改自己那一份。

配置生效后，以下四个功能会走真实模型：

| 功能 | 未配置时的表现 |
|---|---|
| AI 解读 | 回退规则输出 |
| AI 助手 | 回退规则输出 |
| 复核意见 | 回退规则输出 |
| AI 补词建议（termsuggest） | **降级为「仅词表召回候选」**，不报错 |

关闭开关（「启用 LLM」= 关）时全部回退规则输出，这是设计行为，不是故障。

---

## 二、服务端前置：密钥加密密钥（已内置，开箱可用）

### 为什么需要它

配置改成「每人一份」后，用户的三方 API Key 会跟着每个用户**落库**
（`user_llm_config.api_key`）。裸存意味着「拿到库就拿到所有人的密钥」，
所以用 AES-256-GCM 加密，加密密钥取自 `TCM_LLM_ENC_KEY`（32 字节 Base64）。

没有这个密钥时**服务照常启动**，但只要用户真的要保存一个非空 API Key，
就会被拒（HTTP 503 + code=1011），页面显示：

> 未配置 LLM 加密密钥，无法保存密钥（请联系管理员配置 TCM_LLM_ENC_KEY）

### 现状：已经不需要手工配置了

`application.yml` 的 `llm.crypto-key` 带了**开发用默认值**，口径与 `jwt.secret` 一致：

```yaml
crypto-key: ${TCM_LLM_ENC_KEY:dGNtLWVoci1xYy1kZXYtb25seS1sbG0tZW5jLWtleSE=}
```

拉下代码直接跑就能用「导入 LLM」，不会再出现上面那句报错。

### 生产环境：换成随机密钥

```bash
# 1) 演练：看现状 + 打印将生成的密钥，不改任何东西
python tools/init-llm-enc-key.py

# 2) 写入当前用户的持久环境变量（Windows setx）
python tools/init-llm-enc-key.py --apply
```

设置后**必须重启后端**才生效（`LlmSecretCipher` 在构造器里读环境变量）。
注意 `setx` 只对新开的进程生效 —— 先关掉启动控制台窗口，再重新运行 `start-all.bat`。

### 密钥来源与优先级

| 来源 | 优先级 | 说明 |
|---|---|---|
| 环境变量 `TCM_LLM_ENC_KEY` | 高 | 生产用这个；`LlmSecretCipher.resolveKey()` 先读 `System.getenv` |
| 配置项 `llm.crypto-key` | 低 | 上面那行 yml，含开发默认值 |

两者都必须 Base64 解码后**恰好 32 字节**，否则按「未配置」处理（只打一条 warn，不阻塞启动）。

### ⚠️ 换密钥的代价

GCM 密文绑定密钥。**换掉密钥后，已加密落库的 API Key 全部解不开** ——
`decrypt()` 返回空串并告警一次，用户表现为「配置看着还在、但模型调不通」，
需要各自重填一次三方密钥。所以：

- 生产上要把它当**持久密钥**保管；
- 换之前挑好时间窗，并提前通知已配过密钥的用户。

## 三、用户怎么用

1. 登录后点顶栏右侧「**导入 LLM**」。
2. 打开「**启用 LLM**」开关。
3. 选**通道**（二选一）：

   | 通道 | 适用 | 需要什么 |
   |---|---|---|
   | `ollama（本机）` | 本机装了 ollama | 本机 ollama 服务在跑；**无需 API Key** |
   | `openai（含兼容三方）` | 接 DeepSeek / 通义 / 智谱等 | 填**接口地址** + **API Key** |

4. 填**接口地址**：留空用通道默认（ollama=`http://localhost:11434`，
   openai=`https://api.openai.com/v1`）。接三方网关时填它的地址，例如
   DeepSeek 是 `https://api.deepseek.com`。
5. 填**模型名**：从下拉挑，或直接输入自定义模型名。
6. 点左下「**测试连接**」—— 用当前表单里的参数试连一次，**不要求先保存**，
   结果就地显示（通道 / 模型 / 往返耗时 / 一句模型回复）。
7. 确认能连通后点「**保存并生效**」—— **立即生效，无需重启**。
8. 密钥保存后只回显掩码（如 `sk-****abcd`）。**留空表示不修改**；
   想换密钥就填新的再保存。

> 关于保存：通道、模型、接口地址、温度、超时都会保存，重启后仍回显；
> API Key 经 AES-256-GCM 加密后保存在服务端数据库，重启后**仍然生效**，
> 不必每次重填。密钥不会写入 `application.yml`，也不会存到前端。

## 四、常见报错对照

| 页面现象 | 原因 | 怎么办 |
|---|---|---|
| 未配置 LLM 加密密钥，无法保存密钥（503 / code=1011） | 服务端没有合法的加密密钥 | 正常情况已内置默认值。仍出现说明：环境变量 `TCM_LLM_ENC_KEY` 被设成了非法值（解码后不是 32 字节），或后端跑的是老配置 → 重启后端，并核对环境变量 |
| 选择 openai 通道时必须填写 API Key（400） | 选了 openai 但密钥为空 | 填上 API Key |
| 连接失败：…（502 / code=1009） | 「测试连接」探测不通 | 看就地提示：ollama 没启动 / 接口地址写错 / 密钥无效 / 网络不通 |
| 温度需在 0~2 之间 / 超时需在 1000~300000 毫秒之间（400） | 参数越界 | 按提示范围改 |
| 保存失败，本次修改没有生效 | 保存接口报错 | 表单值还在，按上方原因修正后重试 |
| 配置读取失败，下面显示的不是服务端的当前配置 | 拉取配置失败 | 关掉弹窗重开，或检查后端是否可用 |

## 五、和「AI 补词建议」的关系

「标准化质量报告 → 补词」链路上的 **AI 建议**功能走的是同一份 LLM 配置
（`LlmClient` 按 `userId` 取配置）：

- **没配**（或配置不可用）→ 功能**不报错**，只是降级成「仅返回词表召回的候选」，
  即建议里只会出现标准词表里已有的词，`source=dict`；
- **配好了** → 才会真正调模型，出现 `source=model` 的建议。

所以如果在导入页点「AI 建议怎么补」只看到词表命中的候选，先检查这里配好了没有。

## 六、本机补充说明

- `data/llm-config.json`（**未纳入版本管理**）会覆盖 yml 基线的**非密钥字段**
  （enabled / provider / baseUrl / model / temperature / timeout）。
  它只读不回写，所以「数据库里没有用户行、但 GET 配置却显示 openai」
  是因为这个文件在起作用，不是脏数据。
- 相关代码：`LlmSecretCipher`（加解密）、`LlmConfigStore`（基线 + 每人一份）、
  `LlmConfigServiceImpl`（读取 / 保存 / 探测）、`LlmConfigDialog.vue`（前端弹窗）。
- 相关工具：`tools/init-llm-enc-key.py`（生成 / 评估加密密钥）。
