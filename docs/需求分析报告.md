**1 引言**

**1.1 项目背景（含数据现状与流转痛点）**

目前中医临床电子病历以非结构化自由文本为唯一存储形式，由医生自主录入四诊信息、辨证结论、治法方药、病情描述等中医专属内容。原始数据无固定字段、无统一标准、无质量校验机制，导致完整数据链路断裂：原始病历无法被计算机结构化解析，难以完成病历检索、数据统计、合规校验等基础信息化处理工作。

现有业务数据流转存在四大核心问题：

1.  数据输入杂乱：病历文本口语化、术语不统一、字段缺失严重，机器无法解析；
2.  无结构化转换环节：非结构化文本无法拆解为数据库可直接存储的标准化字段，只能以原始文本留存，无法进行数据统计和规整管理；
3.  无质量管控链路：数据错漏、逻辑冲突、方药辨证不匹配等问题无人工 + 机器双重校验；
4.  无标准化清洗输出：原始病历数据规范性差、质量参差不齐，无法直接用于病历统计分析、合规归档、数据复用等基础应用。

本系统承接原始病历数据输入，完成结构化转换、质量校验、数据清洗，最终输出高质量标准化数据集，形成「原始数据输入→加工质控→清洗标准化→本地归档复用」的完整闭环数据流。

**1.2 项目目标（明确整体输入输出总链路）**

系统总输入：医院脱敏原始中医电子病历（TXT/Excel 非结构化文本数据）  
系统总处理：病历入库管理→NLP 智能结构化解析→三层智能质控校验→数据清洗与术语归一清洗→标准化数据集存储  
系统总输出：干净、规范、结构化、可复用的中医电子病历标准数据集，满足中医电子病历规范化整理、质量自查、结构化归档与本地数据复用需求

具体目标：

1.  实现非结构化病历文本自动转换为结构化实体字段，解决机器不可读问题；
2.  建立事前、事中、终末全链路质控体系，过滤错误、缺失、逻辑冲突数据；
3.  完成中医病历专属数据清洗，统一术语、清洗脏数据、融合多源数据；
4.  输出标准化数据集文件，满足病历规范化整理、数据统计、合规归档的基础信息化需求。

**1.3 文档目的**

本文档严格定义系统各模块输入数据、处理逻辑、输出数据、模块间数据关联、全链路数据流转与模块协作关系，明确功能、性能、安全、接口约束，为系统架构设计、数据库设计、前后端编码、系统测试提供唯一依据（本项目不涉及算法自研开发，仅调用成熟 NLP 能力，如开源中医 NER 模型配合正则规则）。

**1.4 项目范围（数据边界清晰定义）**

数据包含范围：原始病历数据录入、结构化转换数据、质控异常数据、数据清洗数据、标准化输出数据集、系统操作日志数据、中医术语库配置数据。  
数据不包含范围：不实现病例智能检索、处方智能推荐、临床数据可视化分析等上层业务功能，系统核心聚焦病历结构化解析与数据质量清洗工作。
（边界说明：质控校验页的"质控检验图谱"属质控结论的可解释性呈现，展示"病历—实体"关联与 LogicChecker 规则冲突边，用于解释判定依据，不涉及临床诊疗决策、病情演化或疗效可视化分析，不属本排除范围。）

**2 业务与用户角色分析（数据操作主体）**

**2.1 用户角色与对应数据权限**

1.  管理员（核心数据操作角色）  
    输入操作：上传原始病历、选择预设质控规则、启动批量清洗任务；  
    处理操作：数据清洗、术语归一、数据集整理；  
    输出操作：导出结构化标准病历数据、归档高质量数据，用于病历规范化留存与本地数据复用。
2.  审核员  
    输入数据：系统自动生成的质控异常病历列表；  
    处理操作：人工复核、修正结构化错误、修正逻辑冲突数据；  
    输出数据：复核完成的合规病历数据。

**2.2 全局整体数据流转总流程（闭环链路）**

外部原始病历数据【输入】→病历管理模块（入库存储）【输出原始病历库】→智能结构化模块（文本解析抽实体）【输出结构化临时数据】→智能质控模块（三层校验筛错）【输出合规病历 + 异常病历】→合规数据直接进入数据清洗模块；异常数据进入人工复核队列，修正后回流二次校验，校验通过进入清洗模块，校验仍不通过则隔离归档、终止流转→数据清洗模块（清洗、归一、融合、去重）【输出高质量标准数据】→标准化数据集持久化存储【系统最终成果】→权限管控导出与本地存储，支撑病历规范化管理与基础数据统计应用

**3 功能性需求（全模块细化：输入 + 处理 + 输出 + 模块关联）**

**3.1 病历数据管理模块（数据入口层，系统首个数据节点）**

模块定位：系统数据总入口，负责原始数据接收、存储、管理，为后续结构化、质控、清洗提供数据源支撑，是所有下游模块的数据来源。  
输入数据：外部批量 / 单条中医电子病历文件（Excel(.xlsx)，单文件最大 50MB，单次最多上传 20 个文件）。

核心处理逻辑：

1.  解析上传文件，校验文件格式、文本完整性，过滤空文件、乱码文件；
2.  分类存储原始病历数据，建立病历唯一 ID，绑定就诊时间、科室、门诊 / 住院标签（标签从文件名或文件内容中解析提取，若无法解析则由用户手动填写）；
3.  提供病历检索、筛选、新增、修改、归档、删除管理能力；
4.  原始数据只读锁定，禁止随意篡改，保证数据源真实性。

输出数据：入库的原始病历数据集（带唯一 ID、分类标签、完整原始文本）。  
模块关联：本模块输出数据 直接输入 智能结构化解析模块，是系统所有后续处理的基础数据源。

**3.2 智能结构化解析模块（核心转换层，非结构化→结构化）**

模块定位：系统核心转换引擎，承接原始非结构化文本，输出机器可识别的中医结构化实体数据，是病历质量校验、数据标准化清洗、病历信息化管理的前置基础环节。  
输入数据：病历管理模块输出的完整原始自由文本病历数据。

核心处理逻辑：

1.  基于开源中医 NER 模型（如 `Monor/hwtcmner` 等 BERT 微调模型）配合正则规则对病历全文分词、实体识别；
2.  实体抽取四诊信息（症状、舌象、脉象）、辨证信息（病因、证候、治法）、方药信息（方剂、中药、剂量）；
3.  建立原始文本与结构化字段的对应映射关系，保留数据溯源关系；
4.  支持人工修正实体抽取错误，修正后数据自动覆盖原记录并更新结构化临时数据表，留存操作日志记录，不实现知识库迭代、规则自动优化等拓展功能。

输出数据：带溯源关系的中医病历结构化临时数据表（包含所有中医实体字段 + 对应原始文本片段）。  
模块关联：本模块结构化结果 全部输入 多层智能质控模块，用于质量校验。

**3.3 多层智能质量控制模块（数据筛选净化层）**

模块定位：对结构化后的病历数据做合规性、完整性、中医内涵逻辑性校验，筛除劣质、错误、冲突数据，为数据清洗提供合格半成品数据。  
输入数据：智能结构化模块输出的带溯源关系的中医病历结构化临时数据表（包含所有中医实体字段 + 对应原始文本片段）。

核心处理逻辑：

1.  事前质控：检测中医病历核心结构化字段缺失（无脉象、无证候、无治法、无病因、无方药等核心必填项缺失），全面标记字段缺失类异常；
2.  事中质控：依托系统内置固定中医诊疗规则完成核心逻辑校验，具体规则包括：

- 证候 - 治法规则：如证候 "风寒感冒"→治法应含 "辛温解表"；证候 "风热感冒"→治法应含 "辛凉解表"
- 证候 - 方剂规则：如证候 "风寒感冒"→方剂应选 "麻黄汤" 类；证候 "风热感冒"→方剂应选 "银翘散" 类
- 证候 - 中药规则：如证候 "风寒感冒"→中药应含麻黄、桂枝等辛温解表药
- 必填项完整性规则：脉象、舌象、证候、治法、方剂、中药为必填项，缺失则标记异常  
    系统仅实现固定规则校验，不支持用户自定义规则编辑功能。

1.  终末质控：对单条病历自动评分、分类统计异常类型、批量汇总质控结果（以扣分明细 + AI 预检单在线呈现，独立报告文件导出列为二期）；
2.  终末质控评分规则：为**相对评分**（以病历自身缺陷项为基础扣分）并按错误类型累计扣分，病历评分满分 100 分，最低扣至 0 分，具体如下：

- 扣分规则：核心必填字段（脉象、舌象、证候、治法、方剂、中药）缺失，每项扣 15 分；辨证逻辑冲突（证候-治法、证候-方剂、证候-中药规则校验不通过），每项扣 10 分；非核心字段缺失、格式错误、重复数据，每项扣 5 分；
- 严重问题定义：核心必填字段缺失 3 项及以上，或证候-治法与证候-方剂规则同时校验不通过，或数据文本无法解析，均视为严重逻辑错误；
- 评分分级：评分 ≥90 分且无严重问题判定为合格，直接进入数据清洗模块；60 分≤评分<90 分，或存在非严重逻辑冲突，进入人工复核队列（复核时限 7 个工作日内）；评分 <60 分，或存在严重逻辑错误且人工复核后仍无法修复，标记为无效脏数据并隔离归档至系统异常数据区，不进入后续清洗流程。

1.  区分合规数据与异常数据，异常数据进入人工复核队列（建议复核时限：7 个工作日内），由审核人员修正后回流本模块二次质控校验；对于人工复核后仍无法修复、存在严重逻辑错误的病历数据，系统自动标记为无效脏数据并统一隔离归档至系统异常数据区，不进入后续清洗流程，实现数据全流程闭环无断点。

输出数据：① 质控合格结构化病历数据；② 待人工复核异常病历数据集；③ 病历质控评分结果与异常统计（以扣分明细 + AI 预检单在线呈现；独立报告文件导出列为二期）。  
模块关联：质控合格数据直接流入数据清洗模块；异常数据进入人工复核队列，审核人员在系统内修正后，数据自动回流至本模块重新执行事前 + 事中质控校验，校验通过后进入清洗环节，校验仍不通过则标记为无效脏数据。

**3.4 数据清洗与数据集导出模块（系统核心，数据终加工 + 成果输出层）**

模块定位：系统最终数据标准化加工核心，对质控合格数据做深度清洗、归一、融合，产出规范、统一、可直接归档复用的高质量结构化中医病历数据集。  
输入数据：质控模块输出的合规结构化病历数据（含人工复核修正后经二次校验通过的完整数据）。

核心处理逻辑：

1.  数据清洗：自动去重、过滤无效脏数据、修补轻度缺失字段、清除乱码冗余文本；
2.  术语归一：依托系统内置中医标准术语库（以 Excel/CSV 格式导入，包含以下内容），统一同义词、别名、口语化表述，实现全库术语标准化：

- 证候术语：来源于《中医病证分类与代码》GB/T 15657-2021
- 中药术语：来源于《中国药典》2025版
- 方剂术语：来源于《中医方剂大辞典》
- 症状术语：来源于《中医临床诊疗术语》GB/T 16751

1.  数据规整处理：统一所有病历数据的结构化字段格式，对重复字段、冗余内容进行合并去重，保证输出数据集字段统一、格式规范；
2.  脏数据隔离：无法修复的劣质数据统一隔离归档至系统异常数据区（与 3.3 节脏数据隔离区一致），禁止进入标准数据集；
    （实现形态说明：隔离归档以 `records.grade='无效'` + `status='invalid'` 落地，不单独建库表或页面，数据集导出仅取 `grade='合格'` → 隔离数据天然被排除；查看入口复用"质控校验"页的预检列表（按 grade 筛选），恢复 / 回滚操作列为二期。）
3.  标准化数据集持久化存储、分类检索、权限管控导出，支持 CSV（UTF-8 编码，首行为字段名）、JSON（数组格式，每个元素为一条病历的结构化字段对象）通用格式输出，留存数据操作日志，保障本地数据安全复用。

输出数据：最终版中医电子病历标准化、结构化、高质量数据集。  
模块关联：本模块输出数据为系统最终成品数据，供病历归档、数据查询、本地数据复用调用。

**4 非功能性需求**

**4.1 性能需求（针对全链路数据处理效率）**

1.  单条病历结构化解析响应时间≤3 秒；NLP 批量解析速度≥30 条 / 分钟（受模型推理速度约束，全库解析属离线批处理，按小时计）；
2.  系统支持规模化病历数据一体化处理（单次批量处理上限 3 万条病历），全链路数据访问采用 SQL 优先（分页游标分批 + 流式导出），不再依赖全表内存过滤；
3.  非 NLP 环节性能基准（3 万条）：全量质控评分重算 ≤3 分钟；单页查询 ≤300ms；统计 / 概览 ≤2 秒；
4.  系统支持单人常规操作、规模化数据处理，保障日常使用、数据处理流程稳定无卡顿、无数据丢失（单机部署场景不做多用户并发优化）。

**4.2 易用性需求**

系统提供简洁可视化操作页面，分层展示原始病历、结构化数据、质控异常数据、清洗后标准数据，支持一键批量处理，操作简单、学习成本低，适配日常数据处理使用场景。

**4.3 可靠性需求（数据流转安全可靠）**

1.  原始输入数据自动备份，防止上传丢失；
2.  批量处理支持任务级进度反馈（同步接口：前端显示"执行中（当前范围：…）"，实时进度条与异步任务列为二期）；失败按条记入失败清单，不自动重试、不回滚整体；
3.  批量操作幂等（重复调用结果一致，复核任务由单条幂等 upsert 收敛）；v1 不支持断点续跑；
4.  异常数据、脏数据自动隔离，绝不污染最终标准输出数据集。

**4.4 兼容性需求**

系统 B/S 架构适配主流电脑浏览器，输出的 CSV、JSON 通用格式，可直接用 Excel、记事本等常规工具打开编辑，适配本地数据整理、归档使用场景。

**4.5 安全性需求**

1.  支持用户登录验证，区分管理员与普通用户基本操作权限；
2.  所有数据流转节点全程留痕，可追溯每一次数据加工、修改、导出行为；
3.  患者隐私数据脱敏处理，禁止原始隐私数据对外输出。

**5 接口需求**

1.  离线文件接口：支持导出 CSV、JSON 通用格式文件，供管理人员本地数据查看、病历统计、档案整理使用。
2.  操作日志导出：支持导出系统操作日志，供管理员审查数据处理过程。

**6 约束与假设（数据流转边界约束）**

1.  输入数据约束：仅接收项目内部脱敏中医病历数据集，不对接医院实时生产数据库；
2.  功能边界约束：本系统仅专注病历结构化解析、质量质控与数据清洗工作，不执行病例检索、数据可视化、处方推荐等拓展业务功能；
3.  数据假设：输入病历数据清晰可解析，无大量无法识别乱码、无严重残缺内容，保证流转加工有效性；人工复核后无法修复的劣质病历数据，统一执行隔离归档处理，不纳入标准数据集。

**7 需求优先级划分（按数据流转核心度排序）**

高优先级（核心数据流必备）：病历数据入库输入、智能结构化转换、三层智能质控、数据清洗与归一清洗、标准数据集导出输出（全链路主干数据流）。  
中优先级：质控报告输出、全流程操作日志记录（数据流辅助保障）。  
低优先级：批量操作模板、数据统计看板、进度显示优化（体验优化，不影响核心数据流转）。

### 数据验证情况
已对500条脱敏样本进行数据分析验证，发现：
- 生僻字问题：存在"面色㿠白"（㿠=U+3FE0），需使用utf8mb4字符集存储
- 方剂命名：样本中方剂名多为"中草药处方"（自拟方），在标准方剂库中未命中属于正常现象
- 剂量单位：存在"3片""5枚"等传统单位，正则表达式需支持g/ml/mg/片/枚/条/张

演示方剂归一效果时建议筛选含经典方名（如"银翘散""桂枝汤"）的病历样本。
