### 严重程度定义

| 级别            | 判定标准                                                                               |
| --------------- | -------------------------------------------------------------------------------------- |
| 🔴 **阻断级**   | 核心用户旅程无法完成，或操作会产生错误数据 / 数据丢失，且用户无法察觉                  |
| 🟠 **严重**     | 核心旅程可以完成，但存在明确障碍、误导性反馈、高风险操作或合规缺陷（含 WCAG A 级失败） |
| 🟡 **一般**     | 存在体验摩擦或信息不准确，用户可通过其他路径绕过、或需额外操作才能达成目标             |
| 🔵 **优化建议** | 打磨项，不影响任务达成，影响专业感、效率或长期可维护性                                 |

**第 4 批联调中发现并修掉两个真实缺陷**（`POST /api/llm/test` 实测暴露；均非本次新增代码引入，而是 OpenAI / Ollama 两条通道的既有问题 —— 此前 `llm.enabled` 恒为 false，该路径从未真机跑过）：

1. **openai 通道永远连不上，且错误信息把矛头指向凭据**：只给 `OpenAiChatModel.Builder` 传同步客户端时，`build()` 会回退到 `OpenAiSetup` 按 `spring.ai.openai.*` 自行装配，而该前缀已统一置 `none`，于是即便 api-key 填了也抛 `At least one credential source must be specified`。修法：同步与异步两个客户端都注入。
2. **ollama 通道的「测试连接」要等 80 秒以上**：`buildOllama` 未应用配置的超时，且 Spring AI 默认重试模板把「连接被拒」也重试 3 次并指数退避（实测 10s / 10s / 50s），远超前端 30 秒超时 —— 用户只会看到一句无用的网络错误，而非「连不上」这个真正原因。修法：显式设连接 / 读取超时，并统一改为不重试（LLM 属可选增强，失败即回退规则，宁可快速失败）。

**验证**：`mvn test` **74/74**；`npm run build` 通过；看板 chunk 12.35 kB → **8.95 kB**。接口在独立实例（`:8081`）实测：缺 api-key → 400、参数越界 → 400、审核员 → 403、无 token → 401、未匹配路由 → 404；密钥只回掩码（`sk-****1234`）不泄明文；探测耗时 **80s+ → 0.11s**。
