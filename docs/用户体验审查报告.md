### 严重程度定义

| 级别            | 判定标准                                                                               |
| --------------- | -------------------------------------------------------------------------------------- |
| 🔴 **阻断级**   | 核心用户旅程无法完成，或操作会产生错误数据 / 数据丢失，且用户无法察觉                  |
| 🟠 **严重**     | 核心旅程可以完成，但存在明确障碍、误导性反馈、高风险操作或合规缺陷（含 WCAG A 级失败） |
| 🟡 **一般**     | 存在体验摩擦或信息不准确，用户可通过其他路径绕过、或需额外操作才能达成目标             |
| 🔵 **优化建议** | 打磨项，不影响任务达成，影响专业感、效率或长期可维护性                                 |

## 三、正向亮点（建议保持）

- 数据域与 RBAC 前后端双闸，越权 403 提示明确，前端按角色过滤菜单。
- 统一使用 `ElMessage` 反馈、写操作普遍有二次确认、空态普遍使用 `el-empty`。
- `TermInput` 自动补全带 200ms 防抖 + latest-wins，输入体验稳定。
- AI 解读卡骨架屏 + 「AI 辅助分析，最终以人工复核为准」声明，人机协同叙事清晰。
- 结构化卡 9 类分区 + `sourceText` 原文溯源 + 归一三级命中展示，可解释性强。
- 主题统一（宣纸底 / 墨绿 / 细线单色），视觉克制；登录页双栏外壳在窄屏下自动收为单栏。
- 长耗时接口均有 loading 兜底，拦截器统一处理 401/403，不会白屏或卡死。
- `html lang="zh-CN"` 正确声明，表单普遍带 `autocomplete` 语义属性。
- 人工复核页「任务卡 + 左右对比 + 术语补全 + 实时预估评分」的同页形态，以及「清洗不会填充医生未书写的内容」这类只讲用户后果的文案，应作为其余页面的统一口径。
