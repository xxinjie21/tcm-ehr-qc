### 严重程度定义

| 级别 | 判定标准 |
|------|---------|
| 🔴 **阻断级** | 核心用户旅程无法完成，或操作会产生错误数据 / 数据丢失，且用户无法察觉 |
| 🟠 **严重** | 核心旅程可以完成，但存在明确障碍、误导性反馈、高风险操作或合规缺陷（含 WCAG A 级失败） |
| 🟡 **一般** | 存在体验摩擦或信息不准确，用户可通过其他路径绕过、或需额外操作才能达成目标 |
| 🔵 **优化建议** | 打磨项，不影响任务达成，影响专业感、效率或长期可维护性 |

## 二、🔴 阻断级

### UX-01 · NLP 结构化解析保存可跨病历覆盖写入

- **所属模块**：结构化解析（`views/NlpExtract.vue`）
- **维度**：`[路径]` 核心操作路径（数据安全）
- **发现日期**：2026-09-19（第一轮 A1）；2026-09-19（第二轮补充「成功提示不可核验」）
- **问题描述**：
  1. 「载入病历」后 `result`（抽取结果）不清空，页面顶部仅显示 `已载入病历：{recordId}` 一行小字；
  2. 「保存到病历」直接以当前 `result` 整体覆盖目标记录的 `structuredData`，无二次确认；
  3. 保存成功的提示为「已保存到病历」，不含登记号、病历 ID 或任何目标标识。
- **对用户的实际影响**：对病历 A 执行抽取后，未注意切换了病历 B 就点保存，会把 A 的结构化结果写入 B 并替换掉 B 已有字段；由于成功提示不含目标标识，用户在事后无法核验写到了哪条病历，错误数据会一路流到质控评分与导出数据集。
- **复现路径**：
  1. 管理员登录 → 结构化解析；
  2. 输入登记号 R1 → 载入病历 → 执行抽取（得到 A 的结果）；
  3. 再输入登记号 R2 → 载入病历（页面未清空上一步结果）；
  4. 点击「保存到病历」→ 无确认直接写入，提示「已保存到病历」。
- **改进方向**：载入新病历（或清空原文）时清空既有抽取结果；保存前给出覆盖确认并明确显示目标病历的登记号/ID；保存成功提示中回显目标病历标识；「保存到病历」按钮在结果为空或未载入病历时给出明确的禁用原因。

## 三、🟠 严重

### UX-02 · 审核员看板 3 个待办卡片中 2 个指向无权限页面

- **所属模块**：首页看板（`views/Dashboard.vue`）、路由守卫（`router/index.js`）
- **维度**：`[导航]` `[路径]`
- **发现日期**：2026-09-19（第一轮 B 已记录「待治理」）；2026-09-19（第二轮补充「病历总数」同为此问题）
- **问题描述**：看板顶部 3 个待办卡片分别跳转 `/review`、`/governance`、`/qc-check`。`/governance` 与 `/qc-check` 的 `meta.roles` 均为 `['管理员']`，而审核员可见「待治理」「病历总数」两张卡片。点击后路由守卫拦截、弹出「无权限访问该页面」并回退 `/dashboard`。
- **对用户的实际影响**：审核员的主落地页就是看板，但看板上 2/3 的入口点了没有反应、只弹一条红色报错；用户无法判断是系统故障还是自己没有权限，也不知道该卡片本不该出现。审核员的有效入口实际只剩 1 个。
- **复现路径**：审核员账号登录 → 首页看板 → 点击「待治理 ›」或「病历总数 ›」→ 停留原页并弹出「无权限访问该页面」。
- **改进方向**：待办卡片按角色渲染（无权限的卡片对审核员隐藏或置灰并标注原因）；或在卡片上直接标注目标页与所需角色；守卫拦截后给出可操作的下一步而非仅报错。

### UX-03 · 看板「开单科室」下拉为硬编码值，与库中实际科室不一致

- **所属模块**：首页看板（`views/Dashboard.vue` 传入 `StatsFilter` 的 `departments`）

  | 导出区 | 「仅导出质控合格病历（21字段），自动脱敏手机号/身份证号；筛选条件复用多条件病历查询。」 | 「21 字段」「复用多条件病历查询」对用户无意义 |

  另需注意：清洗确认弹窗的文案（「将处理**全部病历（不做子集筛选）**…」）与实际行为**相反** —— 代码传的是 `cleanApi({ filters: { ...filters } })`，即按当前筛选范围执行。该问题已在 **UX-08** 记录，本条不重复，但两条建议一并修改。
- **对用户的实际影响**：用户读完这些文案仍不确定三件最关键的事 ——「会不会删数据」「会不会改我写的原文」「这次到底处理了哪些病历」。信息密度高但**有效信息低**，反而增加认知负担；技术词（哈希 / content / 流水线）让页面显得面向开发者而非医生。
- **复现路径**：清洗与导出 → 通读卡片顶部、5 步流程图、按钮旁、导出区四处说明。
- **改进方向**：统一三条原则 —— ① **一句话一个主题**，删除重复表述；② **只讲用户后果**（例：把「原始文本哈希重复标记无效，不删除」改为「重复病历只标记、不删除」；把「精确-包含-模糊三级，content 替换为标准词」改为「把『咽喉痛』这类写法统一成标准术语」）；③ **去掉所有内部概念**（哈希 / content / 流水线 / 21 字段 / 复用查询），需要时以「查看说明」链接承载细节。

### UX-58 · 术语词典页导入提示把数据结构写给最终用户

- **所属模块**：术语词典（`Dictionary.vue` 导入区）
- **维度**：`[反馈]`
- **发现日期**：2026-09-19（第三轮，用户实测）
- **问题描述**：上传区下方三行说明直接把技术规格摊给用户：

  ```
  Excel(.xlsx/.xls) / CSV：需含「标准术语」「别名」两列，可选第 3 列「国标代码」（别名用 、或; 分隔多个）
  JSON：TermEntry 数组 [{standardTerm, aliases[], source?, code?}]
  PDF：走 LLM 智能转换 → 预览确认后入库（需开启 llm.enabled 与 nlp.convert-enabled）
  ```

  其中 `TermEntry`、`standardTerm`、`aliases[]`、`source?`、`code?` 是数据模型字段名；`llm.enabled`、`nlp.convert-enabled` 是配置文件里的开关名 —— 这些都属于实现细节。另外「回滚将使用备份文件覆盖当前词典，并重建内存缓存与 ES 索引」中的「内存缓存 / ES 索引」同样是内部概念。
- **对用户的实际影响**：术语库维护者的诉求是「把这份表导进去」。当前文案要求他理解 JSON schema 与两个开关名才能判断自己该走哪条路径，实际结果是用户不确定自己的文件格式对不对，只能反复试。文件格式本应在**用户选完文件之后**按需提示，而不是一上来全部摊开。
- **复现路径**：术语词典 → 观察上传区下方说明与「版本回滚」卡片提示。
- **改进方向**：① 主行只留一句：「支持 Excel / CSV / JSON；PDF 可智能转换为术语」；② 详细格式（含 JSON 示例）收进「查看格式说明」折叠面板或悬浮提示；③ 开关名不出现 —— 智能转换不可用时，在后端返回的提示里用业务语言说明（后端 `convertFromPdf` 已返回友好文案，前端只需原样展示）；④ 「重建内存缓存与 ES 索引」改为「回滚后词典立即生效」。

## 五、🔵 优化建议

### UX-39 · NLP 按登记号模糊查询取第一条
- **模块**：结构化解析 | **维度**：`[路径]` | **发现日期**：2026-09-19（第一轮 A7）
- **现状**：`loadRecord` 使用 `searchRecords` 模糊匹配并取 `pageSize: 1` 的第一条。
- **影响**：同一登记号存在多条记录时可能载入非目标病历，且用户无从察觉。
- **复现**：结构化解析 → 输入一个存在多条记录的登记号 → 载入的未必是期望那条。
- **改进方向**：改为精确匹配，或在命中多条时给出选择列表。

### UX-40 · 复核「保持待复核（仅重算）」按钮语义可能与结果相反
- **模块**：人工复核 | **维度**：`[反馈]` | **发现日期**：2026-09-19（第一轮 A8）
- **现状**：该按钮不提交修正、仅触发重算，但重算后若达到合格线会返回「已完成」。
- **影响**：按钮名承诺「保持待复核」，实际结果可能是「已完成」，用户对操作结果产生困惑。
- **复现**：人工复核 → 打开一条经重算可达标的任务 → 点「保持待复核（仅重算）」→ 结果提示「已完成」。
- **改进方向**：调整按钮文案（如「仅重算评分」），并说明是否通过由重算结果判定。

### UX-41 · 图谱与看板扩展统计为全表内存聚合
- **模块**：首页看板 / 质控校验 | **维度**：`[加载]` | **发现日期**：2026-09-19（第一轮 A6）
- **现状**：`QcServiceImpl.graph`、`StatsServiceImpl.extra` 使用 `selectList` 全量拉取后在内存统计；当前 500 条数据下响应正常。
- **影响**：按方案目标的数据规模（万级）会出现明显响应劣化，看板首屏与图谱刷新变慢。
- **复现**：当前数据量无法复现，需按目标规模压测后观察。
- **改进方向**：改为 SQL 分组聚合并设置结果上限；在改造完成前明确声明支持的数据规模上限。

### UX-42 · 注册成功后跳转登录页不回填用户名
- **模块**：注册 / 登录 | **维度**：`[表单]` | **发现日期**：2026-09-19（第二轮新增）
- **现状**：注册成功提示「注册成功，请登录」后跳转 `/login`，用户名输入框为空。
- **影响**：用户需要在两步之间重新输入刚填过的用户名，是注册转化路径上不必要的重复操作。
- **复现**：注册 → 提交成功 → 登录页用户名框为空。
- **改进方向**：跳转时带上用户名并回填，光标聚焦到密码框。

### UX-43 · 登录 / 注册仅最后一个输入框支持回车提交
- **模块**：登录 / 注册 | **维度**：`[表单]` | **发现日期**：2026-09-19（第二轮新增）
- **现状**：`@keyup.enter` 只绑定在最后一个输入框（登录的密码框、注册的确认密码框）。
- **影响**：在用户名框按回车没有任何反应，习惯用回车推进表单的用户会以为界面卡住。
- **复现**：登录页 → 在用户名框按回车 → 无响应。
- **改进方向**：在表单容器的输入框上统一支持回车提交，或改用原生表单的提交语义。

### UX-44 · 未定义 `:focus-visible` 样式
- **模块**：全局 | **维度**：`[可访问性]` | **发现日期**：2026-09-19（第二轮新增）
- **现状**：主题中未定义任何焦点样式，键盘焦点完全依赖浏览器默认描边。
- **影响**：深色顶栏（墨绿底）上的「退出」按钮与 AI 悬浮球，默认描边与背景对比不足，键盘用户难以确认当前焦点位置。
- **复现**：任意页面 → 连续 Tab 至顶栏「退出」→ 焦点指示不明显。
- **改进方向**：统一定义 `:focus-visible` 样式，并针对深色底容器单独设定高对比焦点环。

### UX-45 · 主内容区无最大宽度
- **模块**：全局布局 | **维度**：`[布局]` | **发现日期**：2026-09-19（第二轮新增）
- **现状**：`main` 为 `flex: 1`，无 `max-width`，内容随视口线性拉伸。
- **影响**：在 2560px 等超宽屏上，卡片、表格列与图表被拉长，行长过大影响阅读效率，页面观感松散。
- **复现**：将窗口最大化至超宽屏 → 打开首页看板 → 指标卡与图表被拉伸。
- **改进方向**：为主内容区设置最大宽度并居中，或在超宽断点下切换为多列布局。

### UX-46 · AI 助手浮窗与页面底部内容重叠
- **模块**：AI 助手 | **维度**：`[布局]` | **发现日期**：2026-09-19（第二轮新增）
- **现状**：浮窗 `position: fixed` 于右下 26px，展开面板高 480px，覆盖在内容之上。

- **复现**：人工复核 → 展开 AI 助手 → 表格右下角若干行与分页被遮挡。
- **改进方向**：为内容区预留浮窗宽度的安全边距，或允许浮窗停靠/折叠为小图标。

### UX-47 · 无 `<noscript>` 提示与首屏静态占位
- **模块**：全局（`index.html`） | **维度**：`[加载]` | **发现日期**：2026-09-19（第二轮新增）

- **影响**：禁用 JavaScript 或脚本加载失败时，用户看到完全空白的页面，无任何解释或指引。

### UX-48 · 复核「超时」高亮在种子数据下永不触发
- **模块**：人工复核 | **维度**：`[反馈]` | **发现日期**：2026-09-19（第一轮 C）

### UX-49 · 窗口最小宽度无约束
- **模块**：全局布局 | **维度**：`[布局]` | **发现日期**：2026-09-19（第二轮新增）
- **现状**：侧栏固定 176px，主区内边距 20px，未声明最小宽度。
- **影响**：窗口缩至 800px 以下时（如分屏、平板外接），主区可用宽度不足 600px，多列表格与筛选行挤压变形。

- **改进方向**：声明最小宽度并在低于该宽度时给出横向滚动或简化布局。

### UX-50 · 无全局功能搜索 / 快捷跳转
- **模块**：全局导航 | **维度**：`[导航]` | **发现日期**：2026-09-19（第二轮新增）
- **现状**：8 个功能页只能通过侧栏两级分组定位，无搜索、无快捷键、无最近访问。

- **复现**：任意页面 → 尝试通过键盘或搜索定位到「清洗与导出」→ 只能点击侧栏。
- **改进方向**：增加功能搜索（按菜单名与别名）、最近访问记录或快捷键跳转。

## 七、正向亮点（建议保持）

- 数据域与 RBAC 前后端双闸，越权 403 提示明确，前端按角色过滤菜单。

- `html lang="zh-CN"` 正确声明，表单普遍带 `autocomplete` 语义属性。
