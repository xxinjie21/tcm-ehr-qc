## 〇、定位声明

本系统做的是**中医内涵质控**：只对**结构化抽取结果**（`records.structured_data`）与**原始 21 字段**做判定。

**不包含**形式质控（病案首页、书写时限、上级医师查房、日常病程频次、围手术期记录、知情同意书、会诊记录、医嘱单、双划线修正等）。原因是数据模型约束：`records` 表只有 21 个内容字段，**没有**任何「书写完成时间 / 签署 / 手术 / 首页编码」字段。

⇒ 本系统评分与《浙江省住院病历质量检查评分表》等**形式质控表不可直接互比**：那是 100 分制按项目分配，本系统是 100 分扣分制且维度不同。对照关系见 `docs/质控标准与报告口径改造计划.md` §3。

## 一、计分总口径

**总分 100 分，扣分制**（`QcScorer.score`）：

```
得分 = max(0, 100 − 完整性扣分 − 格式扣分 − 逻辑一致性扣分 − 术语标准化扣分 − 重复扣分)
```

各维度扣分**累加**，不设总封顶（单项内部另有封顶的见第五节）。得分下限为 0。

## 二、完整性（核心要素缺失）

判定**病历是否记录了 6 个核心要素**，每项两档扣分：

| 要素 | 结构化 key | 原始列回退字段 | 真缺失 | 漏抽 |
|------|-----------|---------------|--------|------|
| 症状 | `symptoms` | 主诉 / 自诉 / 现病史 | −12 | −6 |
| 疾病 | `diseases` | 西医诊断 / 中医诊断 | −12 | −6 |
| 证候 | `patternList` | 辨证结论 | −12 | −6 |
| 舌象 | `tongueList` | 舌诊 | −12 | −6 |
| 脉象 | `pulseList` | 脉诊 | −12 | −6 |
| 中药 | `herbs` | 草药 | −12 | −6 |

**两档口径**：

- **真缺失（−12）**：结构化结果与原始列**都没有**记录 —— 病历本身没写。
- **漏抽（−6）**：结构化结果里没有，但**原始列有**记录 —— 写了但可能未被抽取。

判定原语：`QcScorer.structuredPresent` / `rawPresent`。结构化列表为空数组等同缺失。

## 三、格式（字段格式）

| 字段 | 类型 | 规则 | 扣分 |
|------|------|------|------|
| 年龄 | regex | `^(\d+(\.\d+)?(岁\|个月\|月\|天)?)+$` —— 数字，可带 岁/个月/月/天 单位，**可组合**（如 `32岁6月`；单位在每组内可选，纯数字 `45` 亦合法） | −5 |
| 性别 | enum | 须为 `男` / `女` / `未知的性别`（白名单唯一权威 = `QcRuleSet.GENDER_VALUES`；`未知的性别` 是真实病历里存在的合法值，见《病历书写基本规范》首页） | −5 |

**放行规则**：字段为空 / 空白 → **不判**（是否必填由别处决定）。正则非法则该项不判，避免误伤。

> 面向用户的说明只输出人话（`hint`），不输出正则本身（`QcRuleDescriber`）。

## 四、逻辑一致性（理法方药）

**判定形式**：当【触发类型】的实体命中【触发值】时，若病历记录了【期望类型】的实体，则其须命中【期望值】之一，否则记冲突。

**关键口径**：

- 触发值 / 期望值**只能来自对应词典**（`data/dictionaries/`）。
- 期望类型实体**缺失 → 不适用（不判）**，不误杀。
- 规则未覆盖的触发值**不判冲突**。
- 每条冲突扣 **−10**（`ConsistencyRule.weight` 默认值；规则名未在规则集中登记时也按 10 计，不让冲突变成 0 分）。

**出厂默认 0 条**（`QcRuleSet.defaults()` 的 `consistency` 为空）。

> 原内置 9 条「证候 → 中药」已移除：固定「证候 → 单味药」对照在真实病历上误报率高达 25%~80%
> （同一证候对应的是复方治法，不是固定两味药），实测把约 1031 次「医生用了别的药」误判成逻辑冲突、
> 强拉待复核；权威（《中医病案质量控制中心建设与管理指南（试行）》）也把理法方药一致性列为
> 人工 / 语义评审，不支持固定对照表。
>
> 需要的组织在「规则配置」里用「触发类型 → 期望类型」自行添加（可选目录保留全部实体类型，
> 含方剂 / 治法）；规则未覆盖的触发值不判冲突。

## 五、术语归一与标准化

术语处理分**两个独立开关**（均在「规则配置」里）：

### 5.1 术语归一范围（`normalization.elementTypes`）

决定**哪些类型的实体做「原文 → 标准词」归一**。

| 项 | 值 |
|----|----|
| 可勾选类型 | 疾病 / 证候 / 症状 / 中药 / 方剂 / 舌象 / 脉象 / 病因 / 治法（9 类，= `EntityTypes.dictKeys()`） |
| 出厂默认勾选 | 疾病 / 证候 / 症状 / 中药 / 方剂 / 舌象 / 脉象 / 治法（8 类；**不含病因**） |
| 空列表 | 合法选择 —— 表示「全部不归一」 |

未勾选的类型：其实体只保留原文、不写 `normLevel`，也不参与下面的未归一扣分。

### 5.2 术语标准化扣分（`standardization.elementTypes`）

对**未命中标准词典**的实体扣分。

| 项 | 值 |
|----|----|
| 可勾选类型 | 同上 9 类 |
| 出厂默认勾选 | 疾病 / 证候 / 症状 / 中药 / 方剂（5 类） |
| 每处扣分 | −1 |
| 档位 | 5 |

**实际计分范围 = 5.2 勾选 ∩ 5.1（归一范围）**：未参与归一的类型，其实体本就不写 `normLevel`，若又计入扣分会被恒判「未归一」而扣满 —— 故取交集。

**分段扣分公式**（不封顶）：

```
未归一数 n ≤ 5  →  扣 n × 1
未归一数 n > 5  →  扣 1 × (5 + (n − 5) / 5)      // 整除
```

即前 5 处线性，之后**每再满 5 处追加一档**（n=10 → 6 分；n=15 → 7 分；n=20 → 8 分）。

**⚠️ 两个容易误读的口径**：

1. **哪些类型计入完全由规则配置决定**：出厂默认只勾 5 类。**舌象/脉象/治法默认不参与扣分**——它们由 python-nlp 按标点先分段抽取，抽不到或词表未收录的段保留原文，默认计入等于拿分段器的行为惩罚用户；勾上即计分（自 2026-10-19 起不再有 `countsUnnormalized` 硬门控，「勾了不生效」已修）。**病因**默认不在归一范围内，需先建好 `causes.json` 并在 5.1 勾上才会归一与计分。
2. 「未归一」的判据是实体**有没有 `normLevel`**，不是「实体在不在词典里」。

## 七、分级阈值

| 阈值 | 默认值 | 含义 |
|------|--------|------|
| `reviewUpper` | **80** | 合格线（复核上限）：得分 ≥ 80 判合格。取值由 35354 份离线仿真的「分数 ≈ 核心要素真缺失数阶梯」推导 —— `weightFull=12` 时 `100−12×缺失数` 得 {100,88,76,64,52}，80 落在「至多缺 1 项合格、缺 2~3 项待复核」的整数台阶上 |
| `invalid` | 60 | 得分 < 60 判无效（缺 ≥4 项核心要素时 `100−12×4=52 < 60`） |

**分级优先级**（从高到低，命中即定级）：

1. 得分 < 60 → **无效**
2. 存在逻辑冲突 → **待复核**
3. 得分 ≥ 80 → **合格**
4. 其余 → **待复核**

> ⚠️ **判定只看分数与冲突**，不再有「真缺失 ≥ 3 直接判无效」这类独立计数条（原 `seriousFullMissing` 已删除）：核心要素真缺失只作扣分项，缺 2~3 项（分 76 / 64）落入「待复核」而非「无效」。
>
> ⚠️ **逻辑冲突优先于分数**：得分 ≥ 80 但存在逻辑冲突的病历仍判**待复核**。
>
> ⚠️ 实测（35354 份真实病历离线仿真，见 `docs/质控规则分级口径优化计划.md` §3.5）：`95 → 80` 使合格率 60.7% → **84.6%**、待复核 27.0% → **4.7%**、无效 12.3% → **10.7%**。

## 八、规则与本文的同步约定

**改规则必须同步改本文。** 由 `QcRuleStandardDocTest` 守卫：

- 断言本文包含**全部**默认一致性规则名（出厂默认 0 条，本项恒为空）、全部完整性要素名（6 个）、全部格式规则 label（2 个）、两个阈值项名与取值（`reviewUpper` / `invalid`）；
- 任一新规则未写入本文 → 测试失败。

**运行时规则说明**（界面「查看完整规则说明」折叠区）由 `QcRuleDescriber.describe()` 从**当前生效规则对象**实时生成，与本文不重复维护数值：本文是**业务标准**，`QcRuleSet` 代码注释是**实现说明**。

**改动流程**：

1. 改 `QcRuleSet.defaults()`（或规则文件）；
2. 同步改本文；
3. 跑 `mvn test`，`QcRuleStandardDocTest` 通过即视为同步完成；
4. 存量病历需**整体重算**，且历史复核结论受影响 —— 先冻结、备份 `records.score/grade/qc_results`。
