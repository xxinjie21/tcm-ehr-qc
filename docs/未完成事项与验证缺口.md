### 5 · AI 异步任务队列满 → 拒绝（AI-2）

- **方法**：把 admin / auditor 的 LLM 指向本地「连接挂起、不响应」端点（`http://127.0.0.1:19999/v1`，`timeout=60000`），使任务卡在模型调用上；随后两账号并发提交 `POST /api/ai/async/termsuggest` 共 120 次。
- **结果**：**202 共 104 次**、**503 共 14 次**、429 共 2 次。
  - 202 恰等于 `POOL_SIZE(4)` + `QUEUE_CAPACITY(100)`，与容量精确一致，证明有界队列按预期接纳；
  - 503 响应体为 `{"code":1012,"msg":"AI 繁忙，请稍后重试"}`；
  - 429 来自 admin 跨批次累计超过「60 次 / 5 分钟」的限流额度（前序验证已消耗 2 次），非缺陷。
- **清理**：验证后已删除两条 `user_llm_config` 记录、停止慢响应服务与两个实例。

### 6 · 多实例异步任务状态共享（AI-28 / R14）

- **方法**：同时起 `:8080` 与 `:19090` 两个实例（共用 Redis db1），交叉提交与轮询 `GET /api/ai/async/{taskId}`。
- **结果**：A 提交 → B 轮询 `HTTP 200` 且带回完整 `reply`（`state=DONE`）；B 提交 → A 轮询同样 200；不存在的 `taskId` → `404 code 1006`。
- 说明：`RUNNING` 状态亦写入共享层，故任务尚未跑完时跨实例轮询返回「还在跑」而非「不存在」。
