### B.3 最易漏

1. openapi 是 BOM + LF（0 个 CR 字节），按 CRLF 写补丁会让整份文件 diff 炸开。
2. 三方一致性脚本只比端点标注，照不出 openapi 全局约定 `:9`，每次改完须人工核对。
3. **注解写跨行会被验证脚本漏检**（2026-10-05 修）：脚本逐行匹配 `@XxxMapping(...)`，而 `@PutMapping({ "路径A",` + 换行 + `"路径B" })` 这种数组写法在该行没有右括号 → 正则失配 → 路径取空 → 整条端点被静默跳过。已在 `collect_backend` 前加 `collapse_annotations()` 拼合跨行注解；修好后端点数由 84 涨到 86（正是 OrgController 的 permissions 双路径）。**凡是「0 差异」的结论，都要连带看一眼端点数有没有莫名下降。**
4. 批次 11「删 `font-weight: normal` 反写」必须与「改基础字重」同批，只删一边会让那 14 处突然变粗。
5. 批次 12 的 TDZ 调序是**改了就 `ReferenceError`** 的类型：调完必须逐页点一遍。
6. 批次 13 四处口径单源要**逐条做**，不要再当笼统项开工。
7. 批次 14 是**只测不改**的批：缺陷回填对应批次，不在本批顺手修。
8. 迁移脚本改完必须跑一次**往返验证** —— `database-init.sql → migration-03-rollback → migration-03 → 再跑一次`，再把两个临时库的建表语句逐行比对。2026-10-05 补正向脚本时正是靠它发现：回滚脚本三处索引守卫写成 `COUNT(*) = 1`，而复合索引在 `information_schema.STATISTICS` 里占两行 → 那三个索引从来没被删掉。
