# 质控规则设计思想

> **来源**：从《质控标准与报告口径改造计划》《质控规则分级口径优化计划》《质控规则与评分标准》《质控提升计划-归一率与抽取正确率》《术语归一与导出准确率提升计划》五份文档中提炼（前两份已收口；后三份为落地成果收口提炼，原计划文档仍保留跟进）。
> **定位**：记录中医电子病历质控系统在分级规则设计上的技术决策、踩坑经验与领域思想。

---

## 一、分级设计思想

### 1.1 为什么是三档而不是两档

**问题**：病历质量是连续的分数，但管理动作是离散的。两档（合格/不合格）太粗——60 分和 90 分都算"不合格"，但处理方式完全不同。

**三档设计**：
- **合格**：直接过，不打扰医生
- **待复核**：有小问题，人工看一眼，可能补两句就行
- **无效**：问题严重，退回重写

**思想**：质控的目的不是"打分排名"，而是"把有限的人工复核精力集中在最需要的地方"。三档设计本质是一个**资源分配问题**——不是所有低分都值得人工介入，也不是所有高分都完全没问题。

### 1.2 为什么要删除硬否决

**原来的设计**：真缺失 ≥ 3 项 → 直接判无效，不管总分多少。

**踩坑**：
- 硬否决和分数是两套独立逻辑，互相遮蔽——一份病历可能总分 85（不错），但因为缺了 3 项被判无效；也可能总分 40（很差），但只缺 2 项，反而不触发硬否决
- 真缺失数和总分高度相关（缺的越多分越低），硬否决是重复惩罚

**新设计**：删掉硬否决，纯按分数线判级。真缺失只是扣分项之一，不再有"一票否决"。

**思想**：不要设计两套并行的判定逻辑。如果一个指标已经在分数里体现了，就不要再单独拿出来做硬规则——那是重复计算，而且会互相打架。

### 1.3 判定优先级的设计

**优先级**（从上到下命中即定级）：
1. 分数低于无效线 → 无效
2. 有逻辑冲突 → 待复核
3. 分数低于合格线 → 待复核
4. 分数 ≥ 合格线 → 合格

**为什么冲突要单独提出来**：逻辑冲突（比如"恶寒"和"大热"同时出现）是**语义矛盾**，不是分数能完全覆盖的。这类问题即使总分高，也值得人工看一眼——因为可能是录入错误，也可能是诊断有误。

**思想**：分数是"全面但模糊"的，规则是"精确但片面"的。好的设计是**分数打底，规则补充**——规则只处理那些分数覆盖不到的特殊情况，不要让规则和分数平起平坐。

## 二、权重设计思想

### 2.1 真缺失 vs 半缺失的权重差异

| 类型 | 权重 | 含义 |
|------|------|------|
| 真缺失（必填项空着） | 12 | 医生根本没写 |
| 半缺失（NLP 没抽出来，但原文有） | 6 | 医生写了，但 NLP 没识别出来 |

**为什么要有区分**：这是**责任归因**。真缺失是医生的问题，半缺失是系统的问题。如果把两者混为一谈，会把系统抽不准的锅扣到医生头上。

**思想**：质控系统要区分"人为错误"和"系统误差"。前者要扣分督促改进，后者要优化 NLP 而不是怪医生。这是医疗 AI 系统的伦理问题——不能让算法的不准变成医生的质量问题。

### 2.2 标准化扣分的 cap 设计

**设计**：标准化（术语未归一）每条扣 1 分，最多扣 5 分。

**为什么要有上限**：术语标准化是个长尾问题——12152 种证候写法，词典不可能全部收录。如果不设上限，一份病历可能因为有 20 个术语没归一被扣 20 分，但其中大部分是词典没收录的边缘写法，不是医生的错。

**思想**：**长尾问题不要用惩罚来解决**。设 cap 是承认"系统做不到完美"，不要让系统的不完美无限放大到医生的评分上。

## 三、领域设计取舍

### 3.1 舌脉治法豁免标准化

**设计**：舌象、脉象、治法三类术语，即使没在词典里，也不扣分。

**为什么**：这三类是中医最个性化、最灵活的部分——同一个脉象，不同医生可能写出十几种写法。强求标准化反而会束缚医生的表达。

**思想**：不是所有东西都应该标准化。**标准化的目标是"可统计、可对比"，不是"统一写法"**。对于需要个性化表达的领域，保持灵活性比追求一致性更重要。

### 3.2 一致性规则的"勿杀"原则

**设计**：逻辑冲突检查只在"两个实体都存在"时触发。如果其中一个实体 NLP 没抽出来，就不判定冲突。

**为什么**：如果实体缺失也触发冲突，那会产生大量误报——因为 NLP 抽取率不是 100%。医生写了"恶寒"，但 NLP 没抽出来，系统不应该因为"没看到恶寒"就判定"大热"有问题。

**思想**：在"误报"和"漏判"之间，选择**宁愿漏判，不要误报**。误报会让医生觉得系统在瞎搞，失去信任；漏判只是少发现一个问题，下次改进就行。

## 四、配置化设计

### 4.1 规则可配置

**设计**：所有权重、阈值都存在 `qc_rules` 表里，组织管理员可以自己调。无配置行时回退到代码里的默认值。

**为什么**：不同等级的医院、不同科室，质控标准不一样。三甲医院的合格线可能要 85，基层卫生院可能 75 就够了。硬编码在代码里，每次调整都要发版——这是不现实的。

**思想**：业务规则要和代码分离。**代码处理"怎么算分"，配置处理"算出来多少算合格"**。前者是稳定的，后者是经常变的。

### 4.2 非法配置守卫

**设计**：如果管理员配错了（比如 `invalid >= reviewUpper`），系统自动回退到默认值并告警。

**为什么**：配置是人的操作，人就会犯错。不能因为管理员配错了一个数字，就导致整个质控系统瘫痪。

**思想**：所有用户输入都要有兜底。配置项也是输入——它可能来自前端表单，可能来自 API，都可能出错。**容错性是系统健壮性的一部分**。

## 五、踩坑总结

| 坑 | 教训 |
|----|------|
| 合格线 95 太高，导致 60% 的病历都"待复核" | 阈值不是拍脑袋定的，要用真实数据仿真验证——先跑一遍看分布，再调线 |
| 硬否决和分数两套逻辑打架 | 不要设计并行的判定体系，一个指标只在一个地方起作用 |
| 标准化不设上限，长尾问题惩罚过度 | 承认系统的不完美，用 cap 控制惩罚的天花板 |
| NLP 抽不准的锅扣给医生 | 区分"人为错误"和"系统误差"，责任要归对地方 |

## 六、归一判定的护栏设计（R1–R7 落地经验）

### 6.1 包含级匹配必须带长度与边界护栏

**踩坑**：旧判据只有 `std.contains(input) || input.contains(std)`，无长度/边界保护。结果"可疑映射"（标准词不足原文一半长）高达 1601 条——如 `无肠鸣漉漉→肠鸣`、`红疹反复发作→斑疹`、`脚气→血`。伪命中一旦进导出件，就是把错词替换进患者病历。

**修复**：归一判定重构为 R1–R7 七条护栏（包含级加"差额 ≤1"、否定护栏、单字不参与、模糊级不否决子串关系等）。35354 份存量实测：可疑映射 **1601 → 19（−98.8%）**；精确命中（L1）八类全部持平，证明收紧没有误伤任何真命中。

**思想**：**"宁可未命中，不错映射"**。错映射的代价是污染导出的患者病历，未命中的代价只是少归一一条（可后续补词典）。症状命中率因此反降 0.9pp（被清掉的 2218 条原本就是错的）——这是预期收益，不是回退。

### 6.2 清洗链路必须幂等

**踩坑**：清洗链路 `GovernanceServiceImpl.clean` 以"已归一的 content"为输入做二次归一，结果非幂等——clean 两次和 clean 一次结果不同，且否定症状（`无黄汗`）会被改写。

**修复**：归一判定接否定护栏，命中必写 `normLevel`；clean 后逐条比对 normalized 增量为 0 才算过（`GovernanceCleanIdempotentTest` 钉住）。

**思想**：任何"再加工"链路都要问自己——**跑两次会不会变？** 会变的链路在批跑、重试、人工补跑场景下就是定时炸弹。幂等性不是优化项，是正确性前提。

### 6.3 三条工程约束：词典唯一、口径一处、影响量化

| 约束 | 内容 | 教训 |
|------|------|------|
| 词典是唯一权威 | 语义等价只由 `standardTerm`/`aliases` 决定，代码里不新造"像不像"的启发式白名单 | 后缀白名单（证/症/病放行）被否——又造一套不可审计的启发式；`湿热下注→湿热下注证` 加一条别名就解决且可审计 |
| 口径只写一处 | 同一判据被两条链路用，必须抽公共方法，禁止两处复制 | `EntityNormalizer.dedupByTerm` 是既有范例；两处复制就是漂移起点 |
| 影响面必须量化 | 任何收紧判定的改动，都要给全量存量"命中率 / 分级分布 / 未命中 TopN"前后对比 | 没有 35k 前后对比，就无法区分"收紧"和"误伤" |

**思想**：**词典是数据，启发式是债务**。能加别名解决的问题不要写规则；写了规则就要在全量数据上证明它没有误伤。

## 七、指标口径与词典运营

### 7.1 验收口径看"原文是否已是标准形态"，不数替换动作

**踩坑**：导出件里 `standardizeMap` 只在替换发生时留痕；若数"替换次数"，已标准化的实体（原文本来就是标准词）就被漏掉，指标虚低。

**设计**：最终口径 = 实体原文落在标准词表（标准词或别名）的比例，与替换动作脱钩。

### 7.2 正确率与归一率数字是两回事

**实测**：症状字段里混着 15422 条问诊整句（`大便日一行`、`晨起小便淡黄`）。把它们移走重抽后，症状归一率反而 **39.77% → 38.48%（降 1.3pp）**——因为移出的分子缩水比例大于分母。

**决策**：仍然必须移。① 它们不是症状，占着分母让归一率失真；② 若照词典补，就是错映射；③ symptoms 字段名实相符。

**思想**：**重抽/清洗提升的是"正确率"，不是"归一率数字"。指标略降属正常，不作为回退依据。** 数字好看但分母是脏的，比数字略降但分母干净更危险。

### 7.3 补词典的铁律：宁可少补，不可错补

**踩坑**：补错一个词会污染所有含该子串的实体——收了 `偏黄`，面色偏黄、小便偏黄、痰偏黄全部被误归。错补的传染面是全体含子串病历。

**教训**：词典运营的收益函数不对称——少补只损失覆盖率，错补污染全库。严格排除噪声（问诊整句、脉舌手法词、2 字残片、属性词）后再入池。

### 7.4 归一与计分是两个独立开关

**设计**：`normalization.elementTypes`（哪些类型做原文→标准词归一）与 `standardization.elementTypes`（哪些类型对未归一扣分）分开勾选；实际计分 = 两者交集。出厂默认归一 8 类、计分只勾 5 类（舌/脉/治法/病因默认不计分）。

**为什么取交集**：未参与归一的类型根本不写 `normLevel`，若又计入扣分，会被恒判"未归一"扣满。

**思想**：**"看不看得见"和"扣不扣分"是两个政策**。导出件标准化率要求全类型尽量归一；但扣分会惩罚系统抽不到的段（如 python-nlp 按标点分段的舌脉）——两个目标不能共用一个开关。

## 八、补充踩坑与被否方案记录

### 8.1 理法方药固定对照表为什么整体移除

**踩坑**：内置 9 条"证候 → 单味药"固定对照，在真实病历上误报率 25%~80%——同一证候对应的是复方治法，不是固定两味药。实测约 1031 次"医生用了别的药"被误判成逻辑冲突，强拉待复核。权威指南也把理法方药一致性列为人工/语义评审。

**修复**：出厂默认一致性规则 0 条；需要的组织自行在配置里加"触发类型 → 期望类型"，规则未覆盖的触发值不判冲突。

**教训**：这是 §3.2"勿杀原则"的重量级实证——**能用人工评审的语义判断，就不要用固定对照表自动化**。

### 8.2 否定词的辖域判定

**踩坑**：否定判定若跨分句、把顿号当界，会让"无 A、B、C"里靠后的项（打嗝）逃过否定；判定集合若收"欠/缺/忌/禁/寡"，"睡眠欠佳""纳欠佳""忌口"这些规范写法会被当否定句误删；"不X"里 X 是症状名自带字（如"不快"）也不能当否定。

**设计**：否定词不跨分句作用；顿号不是分句界（同一否定辖域）；回看长度上限防 O(n²)。

### 8.3 报告类改动必须先清 Redis 缓存

**踩坑**：改了报告逻辑但数字不变——`tcm:ehr:cache:stats:report:*` 的实际 TTL 是 `REPORT_TTL×10`（30 分钟），**重启不会失效**。

**教训**：验证报告改动前先清缓存，否则看到的是过期数字。

### 8.4 被否方案也要落档

**设计**：每个被否的方案连同否决理由一起记录。例如："schema 加 `negated` 字段"要动 Python schema + Java VO + 前端 + 导出格式，收益当前无法被质控/报表消费，性价比低，留待办；"给 12 列加字段标签喂模型"会改变输入分布、结果不可比。

**思想**：**方案被否不是终点，是防止下次重来**。不写理由，三个月后同一个坑会被另一个人重新提一遍。
